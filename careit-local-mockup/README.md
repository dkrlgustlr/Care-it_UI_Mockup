# 케어릿 UI/UX 로컬 목업

2026년 9월 23일 https://app.careit.kr/의 로그인된 화면을 기준으로 제작했습니다.
원본 CSS, Pretendard 폰트, 로고를 로컬에 포함했습니다. 기존 프로젝트 파일은 수정하지 않았습니다.

## 웹에서 보기

[케어릿 UI/UX 목업 열기](https://dkrlgustlr.github.io/Care-it_UI_Mockup/careit-local-mockup/careit-mockup.html)

설치나 로그인 없이 링크로 확인할 수 있습니다. 편집 내용은 각자의 브라우저에만 저장되며, 다른 사람에게 수정 내용을 전달하려면 **수정본 HTML 저장**을 사용하세요.

## 바로 열기

**`careit-mockup.html`을 더블클릭하세요.** Chrome 또는 Edge에서 열면 됩니다.
폰트·이미지·CSS·JavaScript가 이 파일 하나에 들어 있습니다. 설치, 로그인, 인터넷, 서버 실행이 필요하지 않습니다.

## 직접 수정하고 전달하기

1. 오른쪽 아래 **목업 편집**을 누릅니다.
2. **화면 문구 직접 편집**을 켠 뒤 제목, 설명, 버튼 문구 등을 클릭해 바꿉니다.
3. 색상과 카드 모서리를 조절합니다. 레이아웃은 **추가 CSS**에 적고 **CSS 적용**을 누릅니다.
4. 문구 편집을 끄면 메뉴와 버튼을 다시 클릭할 수 있습니다. Esc로도 편집을 종료합니다.
5. **수정본 HTML 저장**을 누릅니다. 내려받은 `careit-mockup-edited.html` 하나를 개발자에게 전달합니다.

편집 내용은 현재 브라우저에 자동 저장됩니다. 브라우저에 저장된 내용만으로는 전달되지 않으므로 반드시 HTML 저장을 눌러 주세요.
다른 탭에서 저장한 새 내용이 감지되면 현재 탭의 저장을 중단합니다. **현재 내용 내려받기**로 이 탭의 내용을 보관한 뒤 **최신 내용 불러오기**를 선택하세요. 저장이 실패한 경우에도 같은 안내에서 내용을 보관할 수 있습니다.
추가 CSS 예시:

```css
/* 홈 카드 간격 */
.recipient-home-grid { gap: 24px; }
/* 페이지 제목 */
.page-header h1 { font-size: 28px; }
/* 일지 입력 영역 */
.journal-card { padding: 32px; }
```

## 포함한 화면과 동작

- 홈, 일지 작성, IEP, 리포트, 기록, 관리대상, 요금제, 설정
- 알림, 관리대상 상세창, 관리대상 추가·수정, 일지 영역 설정
- 저장된 주간 리포트 2페이지와 문항별 판정 펼치기
- 메뉴 이동, 대상·저장 일지·리포트 기간·템플릿 선택, 입력 글자 수, 다크 모드, 모바일 메뉴
- 원본 스타일의 월별 달력: 이전/다음 달, 오늘로, 미래 날짜 제한, 시작일·종료일 범위 검증, 날짜 지우기
- 퀵체크 생성·편집: 선택형/숫자/척도/텍스트/시간 길이/시각, 항목 추가·이름 변경·켜기/끄기
- 관찰 문항 편집: 고시 원문을 참고해 새로 작성한 케어릿 자체 템플릿 3종, 영역·문항 추가/삭제, 글자 수, 도움말, 저장·초기화
- 설정의 로그아웃·동의 철회·계정 탈퇴·대상 삭제 확인창, 대상 비활성화 확인창
- 요금제 내용은 2026-10-06 실제 서비스 기준으로 플러스·팀을 표시. 팀은 3명이 각자 이용하며 1명 결제·최대 2명 초대, 1인당 관리대상 최대 5명, 계정별 기록 분리로 안내.
- 결제 팝업: 선택한 플러스·팀 요금제의 월간/연간 결제 선택, 결제 일정 펼치기, 약관 동의 후 버튼 활성화. 월간은 플러스 14,900원·팀 29,900원(정가 39,900원·시작 이벤트가)이며, 연간은 월 환산 1,000원 할인한 플러스 166,800원(월 13,900원)·팀 346,800원(월 28,900원)을 한 번에 결제. 무료체험·등록된 결제수단·실제 결제 연동은 없음. `#/plans?plan=starter` 또는 `#/plans?plan=team`으로 바로 확인하며, 기존 `plan=pro` 링크도 팀 팝업으로 연결.
- 결제 완료 시연: `결제하기` → 완료 팝업(요금제·결제 금액·결제일·다음 결제일/금액) → 플러스는 일지 작성, 팀은 멤버 초대로 연결. 요금제 화면은 이용 중 카드로 전환하며 전체 요금제 비교는 접어 둠. 선택한 주기에 맞춘 시연 상태를 브라우저에 저장하고 새로고침해도 유지. 이미 이용 중이면 결제 팝업을 다시 열지 않아 중복 시연을 방지.
- 팀 초대 시연: 결제자 1명과 초대 가능한 2자리, 이메일 입력 → 초대 대기 → 초대 취소. 잘못된 이메일·본인 이메일·중복 초대·2명 초과를 차단. 실제 메일·초대 수락·권한 부여·결제 검증은 연결하지 않음. 결제 상태는 요금제 UI 시연용이며 기존 IEP 이용량 시연과 독립적.
- 완료 팝업·이용 중 카드의 `결제 전으로 돌아가기`를 누르면 요금제 선택 화면으로 바로 복귀. `목업 편집 → 결제 시연 초기화`로도 가능. 결제·초대 상태만 초기화하며 기존 일지·관리대상·계획은 유지.
- 리포트 생성·휴지통 이동·복원·완전삭제 확인창, 변경 사항을 버릴 때의 확인창
- 브라우저 안의 임시저장·일지 저장·관리대상 변경, 문구 편집·CSS 편집·HTML 내보내기

## 목업 범위

현재 확인한 화면 구조와 시각 스타일을 재현한 정적 프로토타입입니다. 서비스 전체 코드나 모든 데이터의 복제본은 아닙니다.
원본 서버 저장, 로그인, 계정 삭제, 결제, AI 생성은 연결하지 않았습니다. 서버 요청은 코드와 CSP에서 차단합니다.
원본에 표시된 테스트 계정과 화면 내용을 로컬 예시로 사용했습니다. 전체 기록·모든 기간의 리포트를 가져온 것은 아닙니다.
홈의 통계는 캡처 시점 값입니다. 다른 관리대상 기록은 일부 예시만 포함하며 저장된 리포트 상세는 한 사례입니다.
휴지통은 로컬 목업에서 옮긴 리포트로 동작합니다. 원본 휴지통 데이터와 약관 본문은 포함하지 않았습니다.
AI 동의 본문은 원본 계정에서 현재 다시 열 수 없어 설정 화면 안내를 바탕으로 만든 예시이며, 팝업 안에 예시임을 표시합니다. 실제 동의 등록은 하지 않습니다. AI 다듬기 결과는 입력문을 재사용하고 리포트 생성은 포함된 예시 문서를 표시합니다.
일부 통계와 기존 샘플 리포트 내용은 고정 예시이며 실제 분석 결과를 계산하지 않습니다.
PDF 버튼은 브라우저 인쇄의 PDF 저장을 사용합니다. 원본 서비스의 PDF·Word 생성기는 포함하지 않습니다.
목업 편집 버튼은 전달 작업용으로 추가한 UI입니다.

## 소스 수정

- `index.html`: 화면별 `<template>`과 공통 메뉴. HTML을 직접 수정할 수 있습니다.
- `assets/original.css`: 서비스에서 수집한 CSS. 폰트 경로만 로컬로 변경했습니다.
- `mockup.css`: 로컬 편집 도구와 동작 보완 스타일. 디자인 변경 CSS를 덧붙일 수 있습니다.
- `mockup.js`: 로컬 인터랙션과 예시 데이터.
- `iep.js`, `iep.css`: IEP 목표 입력·계획 검토·수정·대상별 저장과 공통 토큰 기반 스타일.
- `build.py`: 소스를 단일 파일 `careit-mockup.html`로 묶는 스크립트. 외부 패키지 없음.

본문과 하단 회사 정보·구분선은 같은 `--content-max-width` 기준으로 좌우를 맞춥니다. 주요 화면은 최대 1120px, 화면 너비 1440px 이상에서는 최대 1280px입니다. 설정 화면은 기존 최대 680px 폭을 유지하며 하단 정보도 그 폭에 맞춥니다.

일지 제목 옆 연필 아이콘은 [Lucide Pencil](https://lucide.dev/icons/pencil)을 사용합니다. 공식 SVG를 `assets/lucide-pencil.svg`에 보관했고, `index.html`의 아이콘 template에 동일한 SVG를 포함했습니다. ISC 라이선스 전문은 `assets/LUCIDE-LICENSE.txt`와 단일 HTML 주석에 포함됩니다. 아이콘 색상은 기존 UI의 `--muted` 값을 사용합니다.

평소 제목 글자는 메모칸의 왼쪽 경계에 맞춥니다. 제목이나 연필을 누르면 메모칸과 같은 회색 배경과 둥근 모서리가 표시되고, 글자는 메모칸 내부와 동일하게 16px 들여쓰며 연필은 초록색으로 바뀝니다. 밑줄과 그림자는 없습니다. Enter 또는 바깥 클릭으로 편집 상태를 마치면 기본 정렬로 돌아갑니다. 한글 조합 중 Enter는 글자 확정에 사용합니다.

소스를 수정한 다음 이 폴더에서 `python build.py`를 실행하면 전달용 HTML이 갱신됩니다.
소스용 `index.html`도 직접 열 수 있지만 **단일 파일 내보내기는 `careit-mockup.html`에서 사용합니다.**

## IEP 월간 실행 계획

대상 등록은 **구분명(별칭)·연령대** 두 항목만 받습니다. 정확한 생년월일이나 등록용 자유 메모는 받지 않습니다. IEP에는 해당 목표에 필요한 관찰·지원만 적고 보호자의 교육적 요청과 참여·안전 지원은 필요할 때 선택 입력합니다. 세부 구현과 기존 데이터 처리 기준은 `IEP-MINIMUM-DATA.md`를 참고하세요.

왼쪽 **IEP** 메뉴에서 확인합니다. 첫 번째 관리대상에 도움 요청 목표의 합성 예시를 미리 넣었습니다. **AI 계획 제안 받기**를 누르면 법령·고시의 기본 원칙과 자체 양식으로 구성한 7개 항목이 나옵니다: 현행수준 → 교육목표 → 관련 누리과정 → 교육내용 → 교육방법 → 평가계획 → 평가결과.

- 상단 관리대상·연령대 옆에서 월 계획 기간을 기존 범위 달력으로 선택합니다. 미래 날짜를 허용하며 시작일과 종료일은 같은 달 안에서 선택합니다. 주 기간·주 목표 입력은 없습니다.
- 작성 화면에는 **1. 현행수준 / 2. 교육목표**만 표시합니다. 현재 수행 모습과 월 목표가 필수이며, 흥미·강점과 기존 IEP 목표, 필요한 추가 지원은 선택입니다. 기존 일지를 자동으로 분석하지 않습니다.
- **3. 관련 누리과정 / 4. 교육내용 / 5. 교육방법 / 6. 평가계획**은 제안 결과에서 채웁니다. 목업은 도움 요청·또래 놀이·생활 자립의 자체 예시와 일반 구성 규칙을 사용합니다. 연결이 불명확한 목표의 누리과정은 확인 대상으로 남깁니다. 실제 AI 생성은 미연결입니다.
- 평가방법과 평가초점을 분리했습니다. 결과 본문의 **실제 관찰과 평가** 칸에 바로 작성할 수 있으며, 활동 전에는 빈칸으로 저장할 수 있습니다. 다음 계획은 관찰 결과에 따라 교사가 선택하는 조건부 검토안입니다.
- 결과 본문은 일지와 같은 회색 입력칸이며, 별도의 편집 버튼 없이 바로 수정합니다. 저장본을 수정하면 **변경 내용 저장**이 나타납니다. **입력 수정 → 변경 내용 반영**은 입력값을 갱신하며 직접 편집한 연결 문장은 보존합니다.
- **검토 완료하고 저장**하면 **저장한 계획** 탭의 상세 화면으로 이동합니다. **계획 작성**에는 새 초안만 남으며, 저장본 열람·수정 중에도 작성 중인 초안을 보존합니다. 기존 계획 수정은 같은 항목을 갱신합니다. 새 계획은 별도 항목입니다.
- **계획서 보기**로 같은 내용을 표로 확인합니다. **계획서 내려받기**는 표·기간·상태를 포함한 단일 HTML 문서입니다. 다운로드한 문서는 브라우저 인쇄(Ctrl+P)에서 PDF로 저장할 수 있습니다. 내용 수정은 목업에서 하고 다시 내려받습니다. 목업 전체는 기존 **수정본 HTML 저장**으로 전달합니다.
- 계획서에서 비어 있는 선택 항목은 숨기고, 아직 작성하지 않은 실제 관찰·평가는 **미기록**으로 표시합니다. 입력창의 예시·안내는 계획서 본문에 넣지 않습니다. 기존 자료에 잘못된 날짜가 있으면 내용을 보존한 채 달력에서 기간을 다시 선택하도록 안내합니다.
- 기존 초안·저장본은 월간 양식(v4)으로 옮깁니다. 공통 항목의 직접 편집·실제 평가·저장 ID는 유지하고, 기존 주간 입력과 원본은 로컬 `state.iep.monthlyArchive`에 보존합니다. 보관본은 신규 계획 입력이나 개별 계획서에 포함하지 않습니다. 출처 메타데이터는 내부에만 보관합니다.

**AI 호출·실시간 검색·RAG는 연결하지 않았습니다.** 목업은 입력 문장을 보존하고 고정된 설계 원칙으로 결과 틀을 구성합니다. 목표의 의미적 적합성이나 효과를 자동 판단하지 않습니다. 재생성 버튼은 없으며 직접 수정하는 흐름입니다. 예시 결과는 실제 아동의 평가가 아니고, 학교의 공식 IEP 확정 절차를 대체하지 않습니다.

신규 구성 근거는 **특수교육법 시행규칙 제4조**, **유치원 교육과정 고시 제2019-189호**, **자체 작성 규칙과 합성 예시**입니다. 상업 이용 허가가 필요하거나 허용 조건을 확인하지 못한 이전 자료 3개는 신규 사용에서 제외했습니다. 기존 저장본은 당시 출처를 남기며, 새 근거로 검증된 결과처럼 변경하지 않습니다. 자료별 확인 링크·이용 범위·이전 데이터 처리·비용 설명은 `IEP-SOURCE-LICENSES.md`에 있습니다.

IEP를 포함한 최신 목업은 위 GitHub Pages 링크에서 확인할 수 있습니다. 소스 변경은 GitHub에 커밋·푸시한 뒤 Pages 배포가 완료되어야 공유 페이지에 반영됩니다.

## 팝업 보완 사항 (2026-09-23)

- 선택창에 최소 폭을 주고 항목명 줄바꿈을 방지했습니다. 선택 표시는 원본 체크 아이콘을 사용합니다.
- 저장한 일지 수정 목록은 최대 높이 350px로 제한하고, 넘치는 기록은 목록 안에서 스크롤합니다. 화면에 공간이 부족하면 높이를 더 줄입니다.
- 팝업을 브라우저 top layer에 배치해 카드나 모달의 overflow에 잘리지 않게 했습니다. 공간이 부족하면 위로 열고 좌우 위치도 화면 안으로 조정합니다.
- 드롭다운은 방향키/Home/End/Enter/Esc, 달력은 방향키/PageUp/PageDown/Enter/Esc를 지원합니다. 닫으면 트리거로 초점을 돌립니다.
- 달력 월 이동 중 닫히던 문제, 대상 변경 시 리포트의 대상 선택이 사라지던 문제, 큰 편집창의 헤더가 스크롤되어 숨던 문제를 보완했습니다.
- 이전 요청인 일지 상단 3열 동일 너비·한 줄 제목과 투명한 메모 제목·회색 Lucide 연필은 유지했습니다.

브라우저에서 354px 모바일 화면과 1440px 데스크톱 화면을 확인했습니다. 대상 이름 한 줄 표시, 달력 월 이동·날짜 선택·기간 제한과 기록 필터, 퀵체크 추가 후 재조회, 채점 문항 저장, 모달 안 드롭다운, 변경 취소 확인, 리포트 휴지통 이동·복원을 검증했습니다. QA용 파일과 데이터는 전달 ZIP에 포함하지 않습니다.

기록 화면의 필터는 날짜 → 관리대상 순서입니다. 날짜 버튼을 누르면 하나의 달력에서 시작일과 종료일을 차례로 선택하며, 두 번째 날짜를 고르면 기간이 적용되고 달력이 닫힙니다. 시작일과 종료일은 초록색, 사이 기간은 연한 초록색으로 표시하고 마우스와 방향키로 선택할 기간을 미리 볼 수 있습니다. 종료일을 고르기 전에 달력을 닫으면 기존 기간을 유지하며, 시작일보다 이른 날짜를 누르면 그 날짜를 새 시작일로 정합니다. 같은 날을 두 번 누르면 하루만 조회합니다.

오른쪽 초기화 버튼과 달력의 날짜 지우기는 선택 기간을 지웁니다. 대상이나 기록 종류를 바꿔도 기간은 유지합니다. 날짜 필터는 일지의 작성일, 리포트의 생성일, 휴지통의 삭제일에 적용됩니다. 월을 넘기는 기간 선택·같은 날 선택·선택 취소·기간 초기화·354px 모바일 화면과 일지 작성용 단일 날짜 달력을 확인했습니다.

## 리포트 기간 달력

리포트 기간도 기록 화면과 같은 달력에서 시작일 → 종료일 순서로 선택합니다. 기록 화면의 조회 기간과는 별도로 유지하며, 선택한 관리대상의 일지에서 중복 날짜를 제외한 기록 일수를 계산해 생성 기준 3일 충족 여부를 표시합니다. 날짜를 지우면 생성을 비활성화하고, 종료일을 선택하기 전에 닫으면 기존 기간을 유지합니다.

기존 2026년 8월 28일~9월 3일 리포트 예시는 해당 기간을 선택하거나 기록 목록의 보기로 열 수 있습니다. 다른 기간은 생성 확인 대화상자까지만 시연하며, 고정 예시를 새 기간의 실제 결과로 표시하지 않습니다.

## 상태 배지 여백

초안 검토·기록 상태·비활성화·현재 브라우저·요금제 배지는 좌우 8px, 위아래 4px, 줄 높이 20px(전체 최소 높이 28px)을 공통으로 사용합니다. 여백은 `mockup.css`의 `--badge-padding-inline`, `--badge-padding-block`, `--badge-line-height`에서 함께 조정합니다. 글자 수에 따라 배지 너비가 늘어나며 한 줄을 유지합니다.

## 공통 그림자

카드·팝업 등 그림자가 있는 영역은 `mockup.css`의 `--shadow-ui: 0 4px 12px rgba(22,32,42,0.05)` 하나를 사용합니다. 마우스나 선택 상태가 바뀌어도 그림자 값은 같습니다. 회색 입력칸·선택칸·보조 버튼·탭은 그림자가 없습니다. 관리대상 외부 카드의 테두리는 제거했고, 모달 배경막은 35%로 통일했습니다.

투명한 제목·아이콘, 기본 체크 컨트롤, 비활성 버튼, 문서 내부 및 인쇄 영역은 기존의 그림자 없는 구성을 유지합니다. 세부 검수와 적용 내역은 `SHADOW-AUDIT.md`에 있습니다.


## 자체 관찰 템플릿

리포트와 관리대상의 관찰 문항 관리에서 선택합니다. 누리과정 59문항, 초등 1~2학년 25문항, 초등 3~6학년 25문항입니다. 문항별 고시 연결과 사용 범위는 `OBSERVATION-TEMPLATES.md`, 실행 데이터는 `observation-templates.js`에 있습니다. 기존 저장 문항은 유지하며 템플릿 변경·저장 시 새 기준으로 바뀝니다. 기존 리포트 예시는 이전 기준임을 표시합니다. 초등은 2022-33호 원문 버전을 명시한 초안입니다.

자료 출처와 기준 안내는 현재 사용자 화면·IEP 내려받기 문서에 표시하지 않습니다. 개발자용 근거 문서와 내부 출처 메타데이터는 보관하며, 공개 위치와 방식은 추후 결정합니다.

## IEP 이용량·편집 UX 시연 (2026-09-26)

IEP의 `AI 계획 만들기`는 외부 호출 없이 기존 자체 예시를 약 1.4초 후 보여 주는 로컬 시연입니다. 결제 이용기간별 대상당 1회, 스타터 최대 5회·프로 최대 15회를 별도 이용 내역으로 관리합니다. 기본 시연 기간은 9월 26일~10월 26일이며 계획의 월을 바꿔도 갱신되지 않습니다. `목업 편집 → IEP 이용량 시연`에서 요금제, 다음 생성 성공/실패, 다음 이용기간을 바꿀 수 있습니다. 기존 일지·리포트 정책은 변경하지 않습니다.

성공한 결과는 검토 전에도 저장한 계획에 초안으로 남습니다. 실패는 예약을 반환하고, 진행 중 새로고침은 같은 작업을 복구합니다. 결과 수정·저장·다운로드·복사는 이용량을 사용하지 않습니다. 목표를 바꾸면 활동·지원·평가를 다시 확인하며, 관찰이 있는 목표의 변경은 표현 수정/목표 변경을 골라 이전 기록을 보존합니다.

작성 화면의 여섯 입력 항목은 모두 500자로 통일했습니다(전체 최대 3,000자). 일지와 같은 위치·스타일의 `현재/최대자` 표시를 항상 보여 주며, 브라우저 `maxlength`로 한도까지만 입력·붙여넣기할 수 있습니다. 기존에 저장된 장문은 열 때 자르지 않습니다. 결과의 직접 수정은 항목당 2,400자이고 기존 장문은 그대로 보존합니다. 다음 달 복사는 새 문서를 만들며 실제 관찰과 검토 완료 상태를 초기화합니다.

이용량은 브라우저 시연 데이터이며 실제 유료 사용량 통제나 결제 검증이 아닙니다. API 연결·공급자 재시도·실제 원가 집계는 구현하지 않았습니다.
