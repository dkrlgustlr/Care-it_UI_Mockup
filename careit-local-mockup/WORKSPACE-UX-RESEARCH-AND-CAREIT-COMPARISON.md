# 워크스페이스 UI/UX 조사와 케어릿 비교

조사일: 2026-11-08  
목적: 케어릿 목업을 수정하기 전에 워크스페이스의 공통적인 화면 구조와 디자인 기준을 정리한다. 이 문서는 조사와 제안이며, 제품 정책이나 구현 결정이 확정된 것은 아니다.

## 홈 목업에 적용한 수상 서비스 참고

- **Asana**: 2025 Webby Awards ‘Work, Productivity & Collaboration’ 부문 Webby Winner. [수상 목록](https://winners.webbyawards.com/winners/apps-software-immersive/software-services-platforms/work-productivity-collaboration). [Asana 홈 안내](https://asana.com/features/project-management/home)의 오늘 할 일, 최근 작업 위젯과 빠른 이동 구조를 참고하여 케어릿 홈에 ‘오늘의 기록’과 ‘최근 리포트’를 나란히 배치했다. Asana 공식 소개 이미지도 확인했다. 수상은 제품 부문의 수상으로, 해당 홈 화면 자체가 별도 디자인상을 받았다는 의미는 아니다.
- **Adobe Express**: 같은 Webby 부문의 2024 Webby Winner. [수상 목록](https://winners.webbyawards.com/winners/apps-software-immersive/software-services-platforms/work-productivity-collaboration). [교육용 홈 안내](https://helpx.adobe.com/sg/express/web/adobe-express-for-education/for-educators/overview-of-the-new-adobe-express-for-education-home.html)의 빠른 작업 시작과 최근 작업 접근을 참고했다.
- 기존 관리대상 카드는 유지하고, 기존 서비스 소개는 접을 수 있게 아래에 옮겼다. 표시 상태와 최근 리포트는 목업에 저장된 데이터를 사용한다. 위젯 위치 변경이나 크기 조절은 이번 범위에 포함하지 않았다.

### 홈에 적용한 글자와 간격 기준

수상작 Adobe Express와 연관된 Adobe의 [Spectrum 타이포그래피](https://spectrum.adobe.com/foundations/typography/typography-system)는 한국어 등 CJK 본문의 줄높이 1.7배와 제목·구성 요소의 줄높이 1.5배를 안내한다. [Spectrum 간격](https://spectrum.adobe.com/foundations/layout-and-structure/spacing/layout-spacing)은 4·8·12·16·20·24·32·40px 등의 단계를 제공한다. 이것은 Adobe Express의 특정 홈 화면을 그대로 측정한 값이 아니라 Adobe 디자인 시스템의 공개 지침이다.

케어릿의 글꼴과 기존 24·20·16·14px 크기를 유지하면서, 홈에서 다음과 같이 적용했다. 제목과 입력 목록은 1.5배, 여러 줄 기록 본문은 1.7배로 구분했다. 글자 크기는 케어릿의 기존 확대 설정과 함께 변한다.

| 역할 | 케어릿 적용값 | 근거·목적 |
|---|---|---|
| 화면 제목 | 24px / 700 / 1.5 | 기존 케어릿 크기와 Spectrum의 CJK 제목 줄높이 |
| 위젯·구역 제목 | 20px / 700 / 1.5 | 같은 역할의 제목에 같은 규칙 |
| 대상·리포트 이름 | 16px / 600 / 1.5 | 핵심 항목을 보조 상태보다 선명하게 표시 |
| 상태·날짜·보조 문구 | 14px / 400 / 1.5 | 목록의 정보 밀도와 한글 가독성 |
| 기록 본문 | 14px / 400 / 1.7 | 한국어 여러 줄 본문 가독성 |
| 동작 링크 | 14px / 600 / 1.5 | 본문보다 구별하되 과도하게 굵지 않게 |
| 위젯 내부·간격 | 데스크톱 24px, 작은 화면 20px | Spectrum 간격 단계와 케어릿 기존 변수 |
| 큰 구역 사이 | 32px | 케어릿 기존 구역 간격 |

굵기와 폰트 크기, 특정 위젯 배치 수치는 Spectrum을 참고해 케어릿에 맞게 정한 값이며 Adobe Express의 실제 홈에서 확인한 수치라고 단정하지 않는다. 작은 글씨를 모든 홈 화면에 일괄 적용하지 않고 본문의 기존 크기를 유지한다.

### 홈에 적용한 색상 기준

- 후속 정렬 수정: 홈의 상단에 있던 일지 작성·기록 보기 버튼을 제거하고, 대상과 리포트 행의 기존 이동 기능을 유지했다. 위젯과 배너는 왼쪽을 조금 더 넓게 유지하면서 같은 열 기준과 간격에 맞췄다. [Atlassian Grid](https://atlassian.design/foundations/grid)와 [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)의 컨테이너 정렬 원칙을 참고한 케어릿 적용이며, 해당 서비스의 배치를 그대로 복제한 것은 아니다.
- 이후 홈 수정: 상태를 명확히 설명하지 못하는 원과 리포트 장식 아이콘을 제거했다. 상태는 텍스트로 표시하고, 이용 안내와 공지 배너는 각각 전체 영역을 눌러 열 수 있도록 바꿨다. 안내는 브랜드 초록, 공지는 중성 배경으로 구분한다. 아래의 이전 색상 실험에 대한 설명은 조사 기록이다.
- 참고: 2024 Webby Awards 업무·생산성 부문 수상작 Adobe Express와 관련된 [Adobe Spectrum 색상 가이드](https://spectrum.adobe.com/foundations/color/color)는 중성색을 이용해 화면 층을 구분하고, 색이 있는 배경은 제한적으로 사용하며, 상태는 색만으로 전달하지 않도록 안내한다. [Spectrum 디자인 토큰 안내](https://spectrum.adobe.com/foundations/design-data)는 색을 사용 목적에 따라 재사용하도록 설명한다. 이 기준은 제품의 공개 디자인 시스템 지침이며, 수상이 개별 색상 배치에 주어진 상이라는 뜻은 아니다.
- 케어릿 적용: 기존 배경·흰 카드·초록 계열을 유지한다. 홈에서는 가장 중요한 ‘일지 작성’에 초록 채움을 사용하고, 일반 기록의 이동 문구와 리포트 아이콘은 중성색으로 조정했다. 포인터를 올리거나 키보드로 초점을 맞추면 관련 동작이 초록색으로 강조된다.
- ‘작성 완료’는 초록 체크와 텍스트를 함께 사용한다. ‘작성 전’과 ‘임시저장’은 중성 계열 아이콘과 각각의 상태 텍스트로 구분한다. 이용 안내는 연한 민트, 소식·공지 영역은 연한 청회색과 청색을 사용한다. 보조색은 사용자 요청에 따라 케어릿에 맞춰 제안한 색이다.
- 확인한 기본 테마의 텍스트 대비: 흰색/초록 버튼 `#FFFFFF`/`#048857` 약 4.50:1, 중성 보조 문구 `#64707E`/흰색 약 5.05:1, 민트 배경 위 초록 `#06784F`/`#EDF8F3` 약 5.08:1. 어두운 테마의 흰색/초록 버튼 `#FFFFFF`/`#16865F` 약 4.56:1. 사용자 지정 색상은 별도의 대비 확인이 필요하다.
- 소식 영역의 청색 글자 `#365F85`/배경 `#F0F5FB` 대비는 약 6.12:1이다. 다크 모드의 글자 `#AECCE7`/배경 `#203344` 대비는 약 7.78:1이다.

## 조사 범위와 확인 방법

- 미리캔버스: 사용자가 제공한 [디자인 편집기](https://www.miricanvas.com/v2/ko/design2)와 로그인된 [워크스페이스 홈](https://www.miricanvas.com/ko/workspace/drive)을 브라우저에서 직접 확인했다. 홈에서 일부 요소의 CSS 크기와 간격을 확인했다.
- 케어릿: [실제 앱 홈](https://app.careit.kr/)을 직접 확인하고, 현재 로컬 목업의 화면 구조와 스타일 코드를 살펴봤다. 앱과 목업은 데이터·상태가 다를 수 있으므로 구분한다.
- Figma, Notion, Trello, Atlassian: 아래 공식 도움말과 디자인 시스템 문서를 참고했다. 이 서비스들의 로그인된 사용자 화면을 직접 측정한 것은 아니다.
- 측정값은 확인 당시 데스크톱 환경의 CSS 픽셀이다. 해상도, 브라우저 배율, 반응형 구간에 따라 보이는 결과는 달라질 수 있다.

## 핵심 관찰

미리캔버스 홈은 **새 작업 시작 → 내 드라이브의 필터·정렬 → 폴더·디자인 목록** 순서로 배치되어 있다. 편집기로 들어가면 왼쪽에는 도구, 가운데에는 편집 대상, 위에는 공유·다운로드 등 작업 전체에 영향을 주는 기능이 놓인다. 관리 화면과 편집 화면이 각각 다른 목적에 집중한다.

Figma는 파일 브라우저에서 최근 파일과 검색, 폴더·팀 탐색을 제공한다. Notion은 사이드바에서 최근 항목과 즐겨찾기 등 작업 위치로 다시 갈 수 있게 한다. Trello는 홈에 예정된 작업과 최근·즐겨찾기 보드를 보여 준다. 서비스마다 구조는 다르지만, 작업을 시작하고 이전 작업으로 복귀하는 경로를 쉽게 찾도록 구성한다.

현재 케어릿도 홈, 일지 작성, 리포트, 기록, 대상·템플릿 등의 주요 메뉴를 고정 사이드바에서 제공한다. 홈에는 인사·서비스 소개 배너·관리대상 카드와 오늘 기록 완료 수가 있다. 따라서 기존 구조를 버릴 필요는 없고, **매일 쓰는 작업이 홈에서 더 먼저 보이도록 우선순위를 조정하는 방향**이 유력하다.

## 케어릿과의 비교

| 항목 | 참고 서비스의 관찰 | 현재 케어릿 | 개선 검토 |
|---|---|---|---|
| 전역 탐색 | 미리캔버스와 Figma는 작업 공간과 주요 메뉴를 일정한 위치에 둔다. | 왼쪽 사이드바에 홈·일지·리포트·기록·대상·템플릿·요금제·설정이 있다. | 현재 구조 유지. 메뉴 순서와 아이콘 크기, 활성 상태, 접기 동작을 화면 전반에서 통일한다. 메뉴를 늘리기 전에 기존 분류를 먼저 검토한다. |
| 홈 첫 화면 | 미리캔버스는 상단에서 새 디자인을 시작한다. Trello 홈은 다음 작업과 관련 항목을 보여 준다. | 큰 서비스 소개 배너 아래에 관리대상과 오늘 기록 현황이 있다. | 처음 방문자는 소개를 볼 수 있게 하되, 반복 사용 시에는 오늘 기록 현황이나 작성 중인 일지를 먼저 볼 수 있는 접기·축소 방안을 검토한다. 사용성 시험 전에는 효과를 단정하지 않는다. |
| 관리대상 카드 | 작업 공간은 목록에서 항목 이름과 필요한 상태를 보여 준다. | 홈 카드에서 관리대상과 최근 기록 내용, 임시저장 등 일부 상태를 보여 준다. | 이름·오늘 기록 상태·가장 적절한 다음 행동의 위치를 일정하게 한다. 긴 기록 내용은 상세로 이동하거나 짧은 미리보기로 조정하는 방안을 검토한다. |
| 최근 작업 복귀 | Figma와 Notion은 최근 항목을 쉽게 찾아갈 수 있다. | 기록 화면과 홈 카드에서 기록에 접근할 수 있다. | 임시 저장한 일지, 최근 리포트를 홈에서 빠르게 열 수 있는지 검토한다. 최근 항목은 실제 데이터가 있는 경우에만 표시한다. |
| 일지 작성 | 미리캔버스 편집기는 도구와 작업 영역을 분리한다. | 관리대상·템플릿·날짜 선택 아래 퀵체크와 일지 기록을 배치한다. | 현재 입력 순서의 장점은 유지한다. 선택 영역의 폭과 간격, 퀵체크의 입력 형태, 저장 버튼의 시각적 우선순위를 통일한다. |
| 리포트 | 작업 도구는 작업 대상·조건을 결과와 가까운 곳에 둔다. | 작성 대상, 채점 기준, 기간, 생성 버튼 및 결과를 표시한다. | 대상 → 기간·채점 기준 → 생성 가능 상태 → 결과 순서가 쉽게 읽히도록 배치와 간격을 정리한다. 생성 불가 이유는 실제 조건에 맞춰 표시한다. |
| 기록·검색 | Figma는 최근 파일 및 검색을, 미리캔버스는 목록 가까이에 필터와 정렬을 둔다. | 기록 화면에 탭과 대상·기간 필터가 있다. | 제목 → 일지·리포트 탭 → 필터 → 결과 수·목록 순서를 일정하게 유지한다. 검색이나 정렬 추가는 실제 사용량을 보고 결정한다. |
| 정보 보호 | 협업 도구는 콘텐츠 위치·접근 범위를 구분한다. | 홈 카드에 최근 일지 텍스트가 나타날 수 있다. | 공동 공간에서의 화면 노출을 고려해 카드에 보여 줄 내용의 범위를 검토한다. 민감한 내용을 AI가 만들거나 추정하지 않는다. |
| 모바일 | 작업 영역이 좁아지면 도구와 내용의 우선순위를 다시 정해야 한다. | 목업에는 사이드바 접기와 작은 화면 대응 스타일이 있다. | 관리대상 카드·필터·입력 항목을 한 열로 정리하고, 가로 넘침과 주요 버튼 접근성을 실제 기기에서 확인한다. |

## 글자 크기: 측정값과 제안

### 직접 확인한 값

| 요소 | 확인값 |
|---|---:|
| 미리캔버스 ‘내 드라이브’ 제목 | 32px, 굵기 600 |
| 미리캔버스 배너 제목 | 24px, 굵기 600 |
| 미리캔버스 ‘폴더’ 구역 제목 | 20px, 굵기 500 |
| 미리캔버스 내 드라이브 메뉴 글자 | 14px, 굵기 500 |
| 케어릿 실제 홈 인사 제목 | 24px, 굵기 700 |
| 케어릿 실제 데스크톱 사이드바 | 너비 248px |
| 케어릿 목업에 포함된 스타일 변수 | 화면 제목 24px, 구역 제목 20px, 본문 16px, 작은 본문 14px |

미리캔버스의 큰 제목 크기를 그대로 복사하기보다, 케어릿이 이미 사용하는 크기를 토대로 계층을 정리하는 편이 자연스럽다.

### 케어릿 제안값

| 역할 | 제안 | 예시 |
|---|---:|---|
| 화면 제목 | 24px / 700 | 오늘의 일지 작성 |
| 구역 제목 | 18~20px / 600~700 | 관리대상, 퀵체크 |
| 카드 제목 | 16px / 600~700 | 관리대상 이름 |
| 주요 본문·입력 | 16px / 400~500 | 일지 내용 |
| 보조 정보 | 14px / 400~500 | 날짜, 안내 |
| 상태 배지 | 12~14px / 600 | 임시저장, 완료 |

제안값은 확정값이 아니다. 실제 한글 문장, 긴 관리대상 이름, 브라우저 확대와 모바일 화면에서 읽기·줄바꿈을 확인해 조정한다. 작은 글자를 일률적으로 줄이는 방향은 지양한다.

## 간격과 위젯 배치

미리캔버스의 확인한 홈 배너는 약 152px 높이이며, 제목의 왼쪽 내부 여백은 40px이었다. 같은 화면에서 ‘폴더’ 구역의 제목 아래 간격은 8px, 해당 구역의 위쪽 간격은 24px로 확인됐다. 이 값은 특정 화면과 환경의 관찰값이다.

케어릿의 현재 스타일 변수에는 16·20·24·32px 등이 있고, 일지 카드에는 데스크톱 기준 24px 내부 여백이 적용된다. 리포트 생성 카드에는 세로 20px·가로 24px 여백과 20px 간격이 지정돼 있다. 따라서 새로운 숫자를 많이 만들기보다 다음처럼 역할을 정하는 방안을 추천한다.

| 위치 | 제안 시작값 |
|---|---:|
| 아이콘과 글자 | 8px |
| 제목과 바로 아래 설명 | 4~8px |
| 같은 카드 안 항목 | 12~16px |
| 카드 내부 | 20~24px |
| 카드 사이 | 16~20px |
| 큰 구역 사이 | 32~40px |

Atlassian은 8px을 기본 단위로 두고 작은 요소, 카드 내부, 큰 레이아웃 구역을 서로 다른 간격 범위로 다룬다. 케어릿에서는 기존 20px도 사용 중이므로 8px 배수만 강제하기보다 현재 구성과 한글 줄바꿈을 함께 고려한다.

## 홈 구성 초안

1. 날짜와 인사, 오늘 기록 완료 수.
2. 오늘 할 일: 작성 중인 일지, 미작성 대상, 생성 가능한 리포트가 있을 때만 해당 항목을 보여 준다.
3. 관리대상 목록: 이름, 기록 상태, 문맥에 맞는 한 가지 주요 행동.
4. 최근 기록: 일지와 리포트를 식별 가능한 날짜와 대상 정보로 표시.
5. 서비스 소개: 최초 이용 시 보이게 하거나 접을 수 있는 방식 검토.

상태가 없는 항목을 ‘0건’ 위젯으로 무조건 늘어놓기보다는, 빈 상태에서 사용자가 무엇을 할 수 있는지 짧게 알려준다. 홈에 일지 본문을 얼마나 보여 줄지는 사용자 테스트로 정한다. 리포트 생성 가능 여부의 기준은 날짜와 일지 개수 등 실제 정책에 맞춰야 한다.

## 우선순위와 확인 방법

| 순서 | 작업 후보 | 확인할 점 |
|---|---|---|
| 1 | 홈의 소개와 오늘 할 일 배치 비교 | 처음 온 사용자와 반복 사용자가 각각 일지 작성 위치를 찾는지 |
| 2 | 관리대상 카드의 상태·행동 정리 | 기록 전·임시저장·기록 완료 상태를 구분하고 올바른 화면으로 가는지 |
| 3 | 일지 작성의 폭과 간격 통일 | 퀵체크 종류별 줄바꿈, 긴 항목명, 저장 동작을 확인 |
| 4 | 기록·리포트의 대상과 기간 선택 정리 | 대상 변경 시 결과가 일치하고, 생성 불가 이유가 이해되는지 |
| 5 | 타이포·카드·간격 공통 기준 정리 | 같은 역할의 제목과 카드가 페이지마다 불필요하게 달라지지 않는지 |
| 6 | 모바일·접근성 검증 | 작은 화면, 확대, 키보드 포커스, 글자 대비와 클릭 영역 확인 |

실제 사용 시간을 측정하거나 개선 효과를 검증한 것은 아니다. 디자인 수정 전후로 대표 업무를 수행하는 시간과 오류, 사용자 의견을 비교하는 것을 권장한다.
