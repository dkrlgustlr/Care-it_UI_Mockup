# IEP 이용 기준·UX 개선안

> 구현 기준 문서: [케어릿 IEP QA·UX 설계안](IEP-QA-UX-DESIGN.md). 대상별 월 1회와 스타터 기존 일지+리포트 원가 2~3천원을 반영했다. 이 파일의 종전 횟수·원가·상품 제안보다 새 설계안이 우선한다.

> 최신 변경: 사용자의 후속 방향은 **관리대상 1명당 월 1회**다. 아래의 공용 월 20회·60회 제안은 폐기하며, 스타터는 최대 5명 × 1회, 프로는 최대 15명 × 1회로 바꾼다. 비용과 전체 이용 정책은 [일지·리포트·IEP 통합 비용 추정](CAREIT-API-COSTS-2026-09-26.md)을 우선한다. 아래 기존 안은 글자 수·UX 설계와 논의 이력을 위해 보존한다.

작성일: 2026-09-26. 현재 목업의 무료 / 스타터 월 14,900원·대상 5명 / 프로 월 49,900원·대상 15명을 기준으로 한 **출시 전 권고안**이다. 기존 일지·리포트 이용 기준은 변경하지 않는다. 실제 요금제 약관·결제 시스템에 반영하거나 AI를 연결한 것은 아니다.

## 1. 월 생성 횟수

| 요금제 | IEP AI 생성 권고 | 운영 방식 |
| --- | --- | --- |
| 무료 | 계정당 최초 1회 체험 | 매월 지급하지 않음. 이후 직접 작성·수정·복사·보기·내려받기는 허용 |
| 스타터 | 결제 주기당 20회 | 관리대상 최대 5명 사이에서 자유롭게 사용 |
| 프로 | 결제 주기당 60회 | 관리대상 최대 15명 사이에서 자유롭게 사용 |

대상 1명당 평균 4개 계획을 만들 수 있는 용량을 배정한 것이다. 예를 들어 세 목표의 계획과 추가 목표 한 개에 쓸 수 있다. 교육적으로 반드시 4개가 필요하다는 뜻이 아니며, 대상별 4회 제한을 만들지는 않는다. 기관용 요금제는 아직 준비 중이므로 이 안에서 별도 가격을 만들지 않는다.

**1회 = 관리대상 1명의 선택한 월 기간에 대한 월간 실행 계획 결과 1개.** 결과의 여러 섹션은 추가 차감하지 않는다. 한 입력에 여러 목표 문장이 있어도 자동으로 여러 계획을 만들거나 여러 회를 차감하지 않는다. 각 목표를 자세히 다루고 싶으면 사용자가 별도 계획을 만든다. 재생성 버튼은 추가하지 않는다.

### 차감·갱신·초과

- 결과가 정상 완성되어 서버에 복구 가능한 상태로 보관되면 1회를 확정한다. 교사의 검토 완료·저장 버튼을 누를 때까지 기다리지 않는다. 창을 닫았다가 돌아와도 그 결과를 제공하며 다시 차감하지 않는다.
- 검증을 통과한 생성 요청을 시작할 때 1회를 예약한다. 성공하면 확정, 결과를 제공하지 못한 최종 실패이면 반환한다. 공급자 실패 비용은 회사 원가에 별도 기록한다.
- 중복 클릭·두 탭·통신 재연결은 같은 작업을 사용한다. 결과를 삭제하거나 대상자를 비활성화·재등록해도 이미 쓴 횟수는 복원하지 않는다.
- 직접 수정, 입력 반영, 저장, 계획서 보기, 다운로드, 복사는 모두 0회다. API 호출도 없어야 한다.
- 매달 1일이 아니라 **실제 결제 이용기간 시작 시점**에 갱신한다. 예: 9월 26일 결제라면 다음 정상 결제 이용기간이 시작되는 10월 26일에 갱신. 정확한 기간은 결제 시스템이 발급한 period_start / period_end를 사용해 29~31일·윤년·중복 결제 이벤트를 처리한다. 사용자 화면에는 한국 시간의 갱신일을 표시한다.
- 남은 횟수는 이월하지 않는다. 일지·리포트의 횟수와 합쳐 사용하지 않는다.
- 월 한도 소진 시 새 AI 생성만 중단한다. 기존 계획 수정·관찰 작성·복사·다운로드는 계속 사용할 수 있다. 자동 추가 결제와 횟수 충전 상품은 초기 버전에 넣지 않는다.
- 중도 업그레이드를 제공하면 같은 이용기간에서 `새 한도 - 이미 사용한 횟수 - 예약 중 횟수`를 적용한다. 새 한도 전체를 다시 지급하지 않는다. 다운그레이드는 다음 결제 주기부터 적용한다.
- 같은 달에 새로 결제한 것을 이용한 반복 초기화를 막기 위해 결제 이벤트·원래 이용기간을 서버에서 기록한다. 월말 계획을 미리 만들더라도 결과의 계획 월이 아니라 생성 작업을 시작한 결제 이용기간에서 차감한다.
- 구독 종료 뒤에는 새 유료 AI 생성을 제공하지 않는다. 이미 보관한 계획의 열람·직접 수정·내려받기는 유지한다. 무료 체험 횟수는 다시 지급하지 않는다.

일별 생성 제한은 두지 않아 월초에 계획을 몰아서 만들 수 있게 한다. 계정당 동시 생성은 1개, 신규 생성 시작은 분당 최대 3개로 제한한다. 중복 요청·기존 작업 조회는 새로운 생성 횟수로 세지 않는다.

## 2. 입력 글자 수

기존 케어릿 일지의 자유 메모 300자·영역별 500자와 같은 단위를 사용한다.

| 입력 항목 | 최대 글자 수 | 용도 |
| --- | ---: | --- |
| 목표와 관련된 현재 수행 모습 | 500자 | 실제 행동·상황·도움 정도 |
| 흥미와 강점 | 300자 | 이번 목표에 활용할 흥미·강점 |
| 월 목표 | 300자 | 이번 계획의 핵심 목표 |
| 연결할 기존 IEP 목표 | 500자 | 기존 학기·장기 목표 발췌 |
| 보호자의 교육적 요청 | 300자 | 교육적으로 필요한 요청 |
| 활동 참여·안전에 필요한 지원 | 500자 | 계획에서 빠지면 안 되는 조치 |
| 합계 | 2,400자 | 모든 선택 입력까지 채운 경우 |

공백·줄바꿈도 글자 수에 포함한다. 브라우저·서버는 줄바꿈과 한글을 같은 방식으로 정규화한 뒤 동일한 문자 계산을 사용한다. 한글 조합 입력 중간에는 오류를 확정하지 않는다.

기존 요청대로 평소 화면에 `n/n자`를 상시 표시하지 않는다. 입력 중 한도의 90%를 넘으면 남은 글자 수를, 초과하면 줄여야 할 글자 수를 해당 칸 아래에만 표시한다. 붙여넣기·기존 장문을 조용히 잘라내지 않으며 입력과 임시 내용은 보존하고 **AI 생성만 차단**한다. 서버도 같은 제한을 검사한다. 초과한 안전 지원을 AI가 알아서 요약하거나 생략하게 하지 않는다.

기존 저장본의 장문은 그대로 열고 내려받을 수 있어야 한다. 새 제한을 적용하면서 기존 내용을 자동 절단하지 않는다. AI 결과 이후의 수동 편집은 비용과 분리하여 현재 목업의 항목당 2,400자 범위를 유지하고, 기존 초과 자료는 별도 보존한다.

## 3. AI 요청 범위와 내부 비용 기준

### 첫 연결의 권고 설정

- 교사가 쓴 1~2번은 그대로 배치하고, AI는 3~6번의 필요한 제안만 반환한다. 실제 관찰 결과는 빈칸으로 시작한다. 결과는 1안이며 여러 대안을 자동 생성하지 않는다.
- 제안 본문은 1,500~2,000자 정도를 목표로 한다. 이는 상세 실행 방법을 없애는 글자 수 강제가 아니라 반복 문장과 긴 서론을 줄이는 작성 기준이다. 세부 진행·반응별 지원은 남긴다.
- 요청 전체 입력 상한은 **6,000토큰**, 출력·생각 합산 상한은 **4,096토큰**으로 시험한다. 글자 수와 토큰 수는 같지 않으므로 시스템 지시·선택한 근거까지 포함해 실제 토큰을 검사한다.
- 현재 견적의 기준 모델은 기존 검토와 동일한 Gemini 3.5 Flash Standard로 유지한다. 최종 모델 선정은 아니다. 해당 모델의 생각 수준은 low부터 시험하며, 대표 한국어 계획을 정상 완성하지 못하면 모델·지시·분량을 조정하고 원가를 재계산한다. 비용만 맞추려고 잘린 결과를 정상 결과로 제공하지 않는다.
- 1작업의 정상 경로는 모델 생성 1회 + 코드 검사다. 날짜·필수값·출력 구조·자료 ID·금지된 필드 검사는 코드가 한다. 상시 별도 AI 검증·자동 보완 연쇄를 기본 경로로 두지 않는다. 의미·근거 품질 시험에서 별도 모델 검증이 필요해지면 호출 구조와 예산부터 다시 결정한다.
- 일시적 공급자 오류에만 최대 1회의 복구 호출을 허용한다. 잘린 출력이나 내용 불만족에 자동 재생성을 반복하지 않는다. 타임아웃 뒤에는 먼저 기존 작업 상태를 확인하며, 성공 여부를 알 수 없는 작업을 새 작업으로 즉시 중복 호출하지 않는다.
- 실시간 검색·전체 자료집·전체 일지·모든 과거 계획은 넣지 않는다. 허용된 관련 고시 부분과 자체 작성 규칙만 사용한다. HTML·PDF·표·요약 표시·다음 달 복사는 코드에서 처리한다. 공유 결과 캐시에 아동 입력을 섞지 않는다.

### 예상 모델 비용

공식 가격 확인일 2026-09-26. Gemini 3.5 Flash Standard는 입력 100만 토큰당 $1.50, 출력(생각 포함) $9.00이다. [Gemini 공식 가격표](https://ai.google.dev/gemini-api/docs/pricing).

계획 환율은 1달러=1,500원으로 가정한다. 실제 환율이나 실측 사용량이 아니다. 캐시 할인·무료 크레딧은 넣지 않는다.

| 시나리오 | 1회 | 스타터 20회 | 프로 60회 |
| --- | ---: | ---: | ---: |
| 계산용 가정: 입력 4,000 + 출력·생각 합산 3,000토큰 | 49.5원 | 990원 | 2,970원 |
| 모든 호출이 입력 6,000 + 출력·생각 4,096 상한 사용 | 68.796원 | 1,375.92원 | 4,127.76원 |
| 모든 성공 작업에 상한 호출이 2번씩 필요한 스트레스 가정 | 137.592원 | 2,751.84원 | 8,255.52원 |

산식: `(입력토큰 × 1.50 + 출력·생각토큰 × 9.00) ÷ 1,000,000 × 1,500원`.

위 금액은 IEP 모델 호출만이다. 별도로 결과가 남지 않은 실패 작업, 일지·리포트 AI, 서버, 결제수수료, 세금·환전수수료는 포함하지 않는다. 따라서 전체 요금제의 이익을 확정하는 계산이 아니다. 이전 109원/세트와 월 700원 안팎의 추정에는 주간 계획·별도 검증·자동 보완 등 다른 가정이 있었으므로 그대로 비교하지 않는다.

**운영 초기의 IEP 모델 원가 감시선은 스타터 이용기간당 3,000원, 프로 9,000원, 무료 체험 200원**으로 제안한다. 이는 사용자에게 약속한 생성 횟수와 별도의 내부 장애·남용 감지 기준이다. 감시선을 넘으면 원가 원인·실패율을 확인하고 필요 시 해당 생성 경로를 일시 중단한다. 남은 사용자 횟수를 0으로 바꾸거나 조용히 소멸시키지 않는다. 정상 이용에서 감시선에 반복 도달하면 계약한 한도를 축소하지 말고 모델 설정·요금 구성을 다시 검토한다.

서버는 실제 사용량과 진행 중 요청의 최대 예상 원가를 함께 기록한다. 1시간 안에 같은 계정의 생성 작업이 3번 연속 최종 실패하면 신규 호출을 10분 중단하고 운영 알림을 남긴다. 사용자 횟수는 반환하고 임시 작성·복사는 유지한다. 서비스 전체 한도는 계정별 예약·실패 원가까지 합산하여 설정하며 운영 규모를 모르는 현재 단계에서 임의의 고정 총액을 제시하지 않는다.

출력 한도에는 생각 토큰도 포함될 수 있고 한도 도달 시 결과가 잘릴 수 있으므로, 선택 모델·API에서 동작을 검증해야 한다. [공식 생각 토큰 안내](https://ai.google.dev/gemini-api/docs/generate-content/thinking). 토큰 계측은 실제 API 사용량과 청구를 대조한다. [공식 토큰 안내](https://ai.google.dev/gemini-api/docs/tokens).

## 4. 화면과 동작 개선

| 문제 | 바꿀 동작 |
| --- | --- |
| 중복 생성·대기 중 반복 클릭 | 누르면 버튼을 작성 중으로 바꾸고 동일 작업 재사용. 다른 메뉴 이동 뒤에도 작업 상태·결과 복원. 늦은 응답은 다른 대상이나 바뀐 초안에 덮어쓰지 않음 |
| 작은 수정도 재생성될 위험 | 입력 반영·직접 수정은 API 0회. 변경이 없으면 결과로 돌아감. 목표가 바뀌면 활동·지원·평가에 재검토 표시. 이전 관찰은 원래 목표 버전에 보관 |
| 긴 결과 검토 화면 | 활동·지원·평가를 중심으로 표시. 현행수준·목표는 요약/펼침, 세부 준비는 펼침. 실제 관찰·다음 계획은 실행 후 기록 영역으로 구분. 바로 편집 유지 |
| 저장 버튼이 맨 아래 | 긴 스크롤에서도 접근 가능한 저장 영역. 저장하지 않은 변경 상태를 한 곳에만 표시 |
| 다음 달을 다시 작성 | 다음 달 계획으로 복사. 새 ID·기간·미검토 상태, 실제 관찰은 공란. 원본과 작성 중인 다른 초안은 보존. 복사 자체는 0회 |

기존 초록색·회색 입력칸·14/16/20px 문자 체계와 본문 폭을 사용한다. 여러 안내 배지·단계 번호·항목별 탭을 다시 늘리지 않는다. 긴 계획서의 공식 항목 구조는 출력에서 유지한다.

사용자에게 보일 이용량은 버튼 근처 한 줄로 제한한다.

- 기본: `이번 이용기간 20회 중 3회 사용 · 10월 26일 갱신`
- 생성 버튼: `AI 계획 만들기` / 한 줄 보조 표시 `1회 사용`
- 1회 남음: `1회 남았어요 · 10월 26일 갱신`
- 소진: `이번 이용기간의 AI 생성을 모두 사용했어요.` 아래 `직접 작성` / `지난 계획 복사` 제공
- 일시 오류: `계획을 완성하지 못했어요. 사용 횟수는 차감되지 않았어요.` 기존 입력 유지

확인 팝업은 매번 띄우지 않는다. 남은 횟수가 보이는 상태에서 생성 버튼을 누르는 것으로 의사를 확인한다. 기존 기록을 새 목표로 바꾸거나 작성 중인 초안을 덮어쓰는 경우에만 구체적인 변경 내용을 확인한다.

## 5. 목업에 적용할 순서와 확인 기준

1. 입력 항목별 글자 수와 초과 안내, 월 20/60회·무료 1회 체험의 모의 사용량부터 구현한다. 실제 API·결제는 연결하지 않는다.
2. 생성 중·성공·최종 실패·한도 소진을 가짜 응답으로 구현한다. 10회 연속 클릭, 두 탭, 새로고침, 결제 주기 경계에서도 모의 생성 1회만 확정되는지 확인한다. 실제 서버의 보안·청구 통과로 간주하지 않는다.
3. 직접 수정과 입력 반영을 생성에서 분리하고, 목표 변경과 이전 관찰 보존·재검토 표시를 확인한다.
4. 핵심 계획 중심의 결과 화면과 저장 영역을 정리한다. 펼쳐진 입력의 키보드 초점과 오류 연결, 390px 화면을 확인한다.
5. 다음 달 복사와 기간 계산을 구현한다. 기존 계획 불변·새 실제 관찰 공란·API/횟수 0을 확인한다.

연결 직전에는 실제 한국어 입력의 토큰·지연·완료율과 전체 서비스의 일지·리포트 비용을 측정하여 이 권고안의 여유를 확인한다. 사용자가 받은 유료 이용 한도를 사후에 원가만으로 축소하지 않는다.
