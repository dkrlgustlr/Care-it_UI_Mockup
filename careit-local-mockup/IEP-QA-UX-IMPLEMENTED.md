# IEP QA·UX 목업 적용 결과

2026-09-26. `IEP-QA-UX-DESIGN.md`의 사용자 승인 범위를 로컬 목업에 적용했다. 실제 AI/API·결제 연동은 없다. 기존 일지·리포트의 생성 정책과 입력 제한은 바꾸지 않았다.

## 적용

1. **이용량 시연:** 이용기간마다 대상별 1회, 스타터 최대 5회·프로 최대 15회. 시작 시 예약, 결과 보관 성공 시 확정, 최종 실패 시 반환한다. 진행 중 재요청을 막고 새로고침 시 같은 작업을 복구한다. 이름·계획 기간·문서 수를 바꿔도 내역은 유지한다. 기존 같은 월의 생성 계획은 다시 연다.
2. **편집·관찰 보존:** 입력 반영은 기존 결과의 입력 항목만 바꾸며 활동·지원 문장은 보존한다. 월 목표·관찰·참여 지원·연령대가 바뀌면 관련 활동·지원·평가를 다시 확인한다. 관찰이 있는 목표를 바꿀 때 표현 수정/목표 변경을 선택한다. 실제 목표 변경은 이전 계획·관찰을 이력에 보관하고 새 관찰을 비운다. 선택 전 출력에는 이전 목표 기록임을 표시한다.
3. **입력 제한:** 작성 화면의 여섯 입력 항목 모두 500자(전체 최대 3,000자). 추가 사용자 요청에 따라 일지와 같은 우측 상단 `현재/최대자` 표시와 브라우저 `maxlength`로 통일했다. 공통 `updateCounter`를 재사용하며 새 입력·붙여넣기는 한도까지만 허용한다. 저장된 기존 장문은 열 때 자르지 않는다. 결과 수동 편집은 2,400자이며 기존 장문은 열람·다운로드를 유지한다.
4. **결과 구성:** 목표 요약, 활동, 방법·지원, 평가, 접힌 교육과정·준비, 실행 후 기록으로 정리했다. 펼친 내용은 즉시 편집한다. 하단 저장 버튼은 스크롤 중 접근 가능하며 모바일 입력 중에는 고정하지 않는다. 목업 편집 버튼과 겹치지 않는다. 출력은 7개 항목을 유지한다.
5. **다음 달 복사:** 새 ID, 다음 달 1일~말일, 실제 관찰과 완료 상태 초기화. 원본·다른 초안·이용량을 유지한다. 다음 달 계획이 있으면 기존 계획을 열거나 별도 사본을 만든다.

## 시연 방법

`목업 편집 → IEP 이용량 시연`에서 스타터/프로, 다음 생성 성공/실패, 다음 이용기간을 설정한다. 기본 가상 이용기간은 2026-09-26~2026-10-26이다. 성공 결과는 `저장한 계획`에 검토 전 초안으로도 남고, 직접 수정·복사에는 추가 생성권이 필요 없다. 같은 시간대 세 작업이 연속 실패하면 10분간 새 생성만 중단하며 입력과 수동 계획은 유지한다.

## 확인한 내용

- Node 회귀 4종 통과: `iep-usage-ux-check.cjs`, `iep-qa-fixes-check.cjs`, `iep-monthly-check.cjs`, `iep-privacy-check.cjs`.
- 일지와 같은 브라우저 글자 수·줄바꿈·이모지 및 299·300·301·499·500·501자, 월·연도·윤년 경계, 결제일 31일 보정.
- 중복 완료 1회 확정, 생성 중 입력 수정과 수동 작성 보존, 결과 저장 실패 롤백, 실패 예약 반환, 대상/계정 상한, 이름·삭제 플래그·업그레이드·다음 이용기간 처리.
- 입력 반영 시 교사 문장 유지, 실제 목표 변경 시 이전 관찰 보관, 표현 수정 시 관찰 유지, 복사 원본/이용량 보존.
- 초기 검수에서 301자 입력 보존·생성 차단(이후 일지와 같은 입력 제한으로 변경), 생성 성공 1/5회, 목표 이력 생성/현재 관찰 공란, 10월 복사 및 충돌 안내, 대상 전환, 실패 후 횟수 반환, 생성 중 새로고침 후 복구 확인.
- 글자 수 UI 초기 검수(500자 통일 전): 299자에서 두 글자 입력 시 300/300자, 510자 붙여넣기 시 500/500자, 결과 수정칸 18/2400자 표시 확인. 일지의 공통 글자 수 갱신과 14px 스타일을 사용한다. 조합 중에는 보정하지 않고 조합이 끝난 입력에서 한도를 적용한다.
- 390px에서 가로 넘침 없음, 저장 버튼과 편집 도구 겹침 없음, 입력 중 저장 영역 일반 배치. 데스크톱 결과 화면, 7항목 계획서와 빈 관찰 `미기록` 표시 확인. 브라우저 JavaScript 오류 없음.

## 실제 연결 단계에 남는 범위

브라우저 내 사용량은 시연이다. 저장소 삭제를 통한 우회 방지, 서버의 대상/계정 권한 검증, 실제 결제 이용기간, 공급자 응답 유실 조회·재시도, 호출 원가·토큰 집계는 구현하지 않았다. 실제 API 연결 시 별도 검증해야 한다. 현재 복구는 로컬 작업의 동일한 예시 결과를 완성하는 방식이며 공급자 API를 호출하지 않는다. 이전에 구현한 저장 충돌 검사를 그대로 사용한다.

검수 파일은 `_qa/`의 합성 데이터이며 전달용 ZIP에 넣지 않는다.
