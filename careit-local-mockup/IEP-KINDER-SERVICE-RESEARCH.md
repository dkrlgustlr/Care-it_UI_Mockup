# 유치원 AI IEP 실제 화면 조사

조사일: 2026-11-22. 사용자가 외부 Chrome에서 열어 둔 [유치원 AI IEP v9.0](https://kinder2025.web.app/)의 로그인된 화면을 확인했다. 학생 목록이 비어 있어 실제 학생·목표 데이터, 생성 결과, AI에 전달되는 입력 범위, 저장과 내보내기 결과는 확인하지 못했다. 화면 탐색 외에 학생 추가, 생성, 저장, 삭제, 자료 업로드 또는 외부 전송을 실행하지 않았다. 각 명칭은 확인한 제품의 화면 기준이며 모든 유치원이나 나이스의 필수 항목이라는 뜻은 아니다.

## 전체 흐름

상단에 학생 선택, 학년도·학기, 학기 적용, 이전 학기, 학생 추가, 저장, 삭제, 백업이 있다. 학생 선택 전에는 학년도·학기 및 학기 전환이 비활성화된다. 내보내기 안내에는 나이스에 직접 연동하거나 결재하지 않고 초안을 복사해 붙여넣는다고 표시한다.

1. **인적사항**: 이름(가명 안내), 성별, 생년월일, 학급명, 선정배치영역, 복지법상 장애, 장애정도. 케어릿에 일괄 필수로 도입할 근거는 아니며 필요성·처리 근거를 따로 검토한다.
2. **배치·지원계획**: 특수학급과 통합학급 각각의 활동 내용·방법과 담당 교사.
3. **관련서비스**: 치료지원의 세부 영역·기관·시간·기간·장소, 방과후과정, 통학, 지원인력, 보조공학, 가족·상담·정보접근의 지원 사항.
4. **현재학습수행수준**: 신체운동·건강, 의사소통, 사회관계, 예술경험, 자연탐구 각각의 강점과 지원요구. 생활지원은 선택 영역이다.
5. **학기별 IEP**: 각 영역에 현재학습수행수준·장기목표·단기목표·교육내용·교육방법·평가계획을 편집한다. 영역별 접기와 AI 초안 작성 버튼을 제공한다. 별도 목표별 관리에는 영역, 목표 추가, 영역 문장에서 목표 만들기, 목표를 단기목표 칸에 반영이 있으며, 화면 설명상 목표별 기간·지원 수준·평가 기준·진행 상태를 관리한다. 학생과 목표가 없어 추가 후 실제 편집 화면은 확인하지 않았다.
6. **지원팀 회의록**: 원문 메모, 회의 일자·장소, 참석자 역할, 보호자·교사·관련서비스 의견, 강점, 지원 요구, 배치·통합 지원, 합의 목표, 가정연계, 결정 및 후속 조치. 입력 저장과 AI 회의록 작성 버튼이 있다. 참석자 실명 대신 역할을 입력하라고 안내한다.
7. **학기별 평가**: 목표별 관찰의 날짜·상황·도움·수행 내용·근거, 영역별 누가기록, 월별 실행계획·평가, 학기말 평가 보고서. 관찰을 누가기록에 반영하는 명시적 버튼이 있다. 화면은 유아 간 비교나 점수 대신 같은 목표 안에서의 변화를 안내한다. 기본 1학기 화면에는 3~8월 칸이 보인다.
8. **종합보고서·내보내기**: 인쇄, 보고서 복사, 학부모용·교사용, 전체·영역별·관련서비스·평가 요약 복사, 누락 항목 점검, 인계 자료. 문서 보관 상태는 작성 중·검토 중·확정·수정이며 확정 당시 스냅샷과 수정 사유가 안내된다. 앱 상태와 나이스 승인 상태는 다르다고 명시한다.
9. **놀이계획**: 이번 주 놀이 주제를 입력하는 주간 놀이계획 생성 화면.
10. **활동안**: 놀이 주제, 대상 연령, 놀이 목적, 누리과정 관련 요소를 입력하는 교수학습 과정안 생성 화면.
11. **자료실**: IEP 목표와 놀이 주제를 입력하고 놀이 아이디어 또는 시각 자료를 요청하는 화면. 별도 이미지 생성과 인쇄도 표시된다. 결과는 미확인.
12. **문서/OCR**: PNG·JPG·WEBP·PDF 업로드(화면상 최대 10MB), 추출 결과 편집과 복사 화면. 업로드나 실제 추출은 시험하지 않았다.
13. **업무 보조**: 공문, 알림장, 체크리스트, 특수교육 업무 등을 위한 별도 서비스 링크. 계정 연동은 실행하지 않았다.

## 케어릿에 적용할 관찰과 원칙

- 한 대상·학기 아래 여러 영역과 여러 목표를 두고, 목표별 현재 수준→장기·단기 목표→교육내용·방법→평가를 연결한다. 현재 케어릿의 단일 월 목표 구조를 확장하되 저장된 계획을 보존해야 한다.
- 영역별 강점과 지원요구는 좋은 시작점이다. 관찰 사실의 상황·행동·지원·일시를 필요 시 기록하도록 돕고, 모든 칸을 필수로 강제하지 않는다.
- 학기 계획과 월별 실행, 평가계획과 실제 평가, 계획 목표와 실제 관찰을 구분한다. 관찰이 없으면 결과를 자동으로 채우지 않는다.
- 목표별 관찰을 선택해 쌓고, 다른 목표나 다른 대상과 섞이지 않게 한다. 기존 일지 연결은 사용자가 기록을 선택하는 후속 기능으로 다루며 현재 자동으로 일지를 읽지 않는 정책을 유지한다.
- 계획 내용과 목표별 구조화 데이터의 양방향 반영은 덮어쓰기 전에 차이를 보여주고 선택·취소할 수 있도록 설계한다. 이 서비스의 버튼은 확인했으나 실제 덮어쓰기 동작은 시험하지 않았다.
- AI는 질문과 편집을 돕고, 출처가 확인된 입력 사실과 목표·활동 제안을 구분한다. 실제 관찰, 횟수, 진단이나 성공을 임의로 채우지 않는다. 사용자가 선택한 항목만 반영하고 직접 저장한다.
- 회의록·관련서비스·보호자 의견은 현장에 유용하지만 민감할 수 있으므로 작성 목적과 역할을 분명히 하고 선택적으로 수집한다. 나이스 필드를 그대로 기본 필수로 복제하지 않는다.
- 나이스 출력은 대상·학기·영역 확인 후 항목별 복사부터 검토하며, 복사 여부와 공식 승인·마감은 다르다. 학교급·교육청별 양식은 실제 현장 확인 전 확정하지 않는다.
- OCR은 원본과 추출 결과를 보여주고 수정·부분 선택을 허용하며 실패 시 입력을 보존한다. 파일 자체가 AI 업체에 전송되는지, 저장 기간·동의·처리 경로는 실제 구현 전 별도 설계가 필요하다.
- 긴 학기 계획은 영역 선택과 접기, 명확한 저장 상태, 다음 행동 중심으로 구성한다. 모바일은 현재 편집 항목에 집중하고 AI는 별도 패널로 여닫는다.

## 검증이 필요한 사항

- 학생 추가 후 영역별 목표의 실제 입력 필드와 필수 조건, 목표·관찰 간 연결 및 불일치 처리.
- 생성 전 수집되는 실제 정보와 AI 전송 범위, 결과 품질·편집·복구·저장 방식.
- 학기 전환·이전 학기 불러오기·확정 스냅샷의 세부 동작과 이전 데이터 보존.
- 실제 나이스 항목과 양식이 학교급·교육청별로 다른 부분, 평가 시기, 관련서비스 기록 필요성.
- 현행 서비스는 로그인된 상태의 빈 화면과 설명만 직접 확인했으며 실제 생성 기능의 품질이나 나이스 공식 연동을 확인한 것은 아니다.
