# 케어릿 IEP QA·UX 설계안

작성일: 2026-09-26. 사용자와 정리한 비용·이용 방향을 기준으로 작성한 설계안이다. 이 문서가 종전 월 20회·60회 제안보다 우선한다. 이후 사용자 승인에 따라 화면·로컬 시뮬레이션을 구현했다. 실제 AI·결제·서버 이용권은 연결하지 않는다. 구현과 검수 범위는 `IEP-QA-UX-IMPLEMENTED.md`에 정리했다.

## 1. 설계 기준

| 항목 | 기준 |
| --- | --- |
| 기존 원가 | 스타터 5명 전체의 일지+리포트 월 API 비용 2,000~3,000원이라는 사용자 제공 계산 유지 |
| IEP 추가 원가 | 대상별 월 1회, 5명 × 예상 49.5원 = 247.5원 |
| 통합 기준 | 스타터 월 약 2,250~3,250원. 실제 측정값이나 보장되는 최대 청구액은 아님 |
| IEP 이용량 | 결제 이용기간마다 대상별 AI 생성 1회. 스타터 전체 최대 5회, 프로 최대 15회. 다른 대상에게 횟수 몰아쓰기 불가 |
| 변경하지 않을 것 | 기존 일지·리포트 한도·가격·모델·입력 규칙. 앞서 가정한 리포트 월 5회 제한을 이번 설계로 확정하지 않음 |
| 기본 사용자 경험 | 교사는 1~2번만 입력하고 제안을 받은 뒤 모든 내용을 바로 수정. 주 계획과 재생성 버튼은 없음 |
| 현재 구현 범위 | 실제 AI를 연결하지 않은 목업. 대기·성공·오류·이용량은 모의 상태로 검수 |

프로의 기존 일지+리포트 원가는 확인되지 않았으므로 스타터 원가를 단순 3배 하여 확정하지 않는다. 자세한 비용 기준은 [통합 비용 문서](CAREIT-API-COSTS-2026-09-26.md)의 최신 기준을 따른다.

## 2. 우선순위별 해결안

### P0-1. 생성 횟수와 중복 요청

**월 = 실제 결제 이용기간**으로 정의한다. 계획의 대상 월과 이용량 갱신일을 구분한다. 기간은 서버가 결제 시스템에서 받은 시작·종료 시각을 쓰며, 화면에는 한국 시간의 다음 갱신일을 표시한다. 계획 기간을 다른 달로 바꿔도 사용한 생성권이 다시 생기지 않는다. 동일 대상·동일 계획 월의 이미 생성된 계획은 다음 결제 주기에 다시 열어도 재생성하지 않고 기존 결과로 연결한다.

- 대상별 1회와 계정 전체 5/15회 한도를 함께 검사한다. 이름 변경·대상 삭제·비활성화·재등록·계획 삭제로 계정 이용량을 되돌리지 않는다. 새 대상을 추가해도 현재 결제 이용기간의 총 지급량은 늘어나지 않는다.
- 사용하지 않은 횟수는 이월하지 않는다. 구독 중복 결제 알림이나 단순 새로고침으로 횟수를 다시 지급하지 않는다. 중도 업그레이드도 이미 사용한 대상과 계정 이용량을 유지한다.
- 요청 전 필수 입력·날짜·글자 수·사용 가능 여부를 확인한다. 검증 오류에는 예약도 모델 호출도 없다.
- 생성 시작 시 1회를 예약하고, 성공 결과가 안전하게 보관되면 1회 확정한다. 별도의 검토 완료·저장을 기다리지 않는다. 최종 실패이면 예약을 반환한다. 실패한 모델 호출 원가는 별도 기록한다.
- 계정당 동시 생성 1개. 다른 대상을 선택해도 진행 중인 작업을 잃지 않고, 진행 중에는 새 생성만 막는다. 이미 작성된 문서 열람·수정은 가능하다.
- 동일 작업의 연속 클릭·새로고침·두 탭 요청은 중복 실행하지 않는다. 입력 내용·대상·계획 기간은 시작 시점의 스냅샷에 묶는다. 늦게 도착한 응답을 현재 선택한 다른 대상이나 수정된 입력 위에 붙이지 않는다.
- 요청 시간이 길어진 것만으로 즉시 실패 처리하거나 새 호출을 보내지 않는다. 작업 상태를 확인하고 완료된 결과가 있으면 복구한다. 사용자는 계속 수동 작성할 수 있다.
- 자동 복구 호출은 일시적 공급자 오류에 한해 작업당 최대 1회다. 내용이 마음에 들지 않거나 결과가 잘렸다는 이유로 자동 생성·검증·보완을 반복하지 않는다. 1시간 안에 같은 계정에서 3개 작업이 연속 최종 실패하면 새 생성은 10분 쉬고 운영 오류로 기록한다. 생성권은 소진으로 바꾸지 않고 수동 편집은 유지한다. 공급자 전체 장애도 공통 경로에서 중단해 실패 호출이 계속 쌓이지 않게 한다.
- 이용량을 모두 쓰면 `이번 이용기간 사용 완료 · 다음 이용 10월 26일`과 `계획 보기`를 보여준다. 별도 수동 계획 작성·복사는 가능하다. 추가 결제·재생성 버튼은 넣지 않는다.

**완료 기준:** 같은 대상에 연속 10회 클릭하거나 서로 다른 입력으로 두 탭에서 동시에 요청해도 현재 이용기간의 성공 생성은 최대 1개다. 스타터의 전체 성공 생성은 최대 5개다. 사용자가 문서를 저장하지 않아도 결과는 재열기 가능하며 차감은 한 번뿐이다.

### P0-2. 입력 수정과 AI 생성 분리, 이전 관찰 보호

- 새 계획의 첫 `AI 계획 만들기`만 생성권을 사용한다. 생성 이후의 직접 입력·입력 반영·저장·다운로드·화면 이동은 API 0회다.
- 입력 변경이 없으면 기존 결과를 보여준다. 오탈자 하나 고쳤다고 전체 결과를 다시 생성하지 않는다.
- 월 목표·현행수준·참여 지원이 바뀌면 연결된 활동·교사 지원·평가 항목에 `다시 확인` 표시를 붙인다. 어떤 내용이 달라졌는지 한 줄만 알리고, 교사가 직접 고친 문장을 유지한다. 의미 분석용 AI 호출은 추가하지 않는다.
- 입력 중에는 임시 내용만 보존하고, 글자마다 목표 버전이나 확인 팝업을 만들지 않는다. 수정 후 저장할 때 한 번의 변경 단위로 처리한다.
- 실제 관찰이 없는 계획에서는 목표 변경 뒤 관련 항목을 확인하고 저장하면 된다. 실제 관찰이 있는 상태에서 목표 문장이 달라진 경우에만 저장 영역에서 `표현만 수정` / `목표 변경`을 선택하게 한다. 자동으로 의미를 추측하지 않는다.
- `표현만 수정`은 기존 관찰을 유지한다. `목표 변경`은 변경 전 목표·계획·관찰을 함께 보존하고 새 목표의 실제 관찰은 공란으로 시작한다. 이전 관찰은 `이전 목표 기록`에서 볼 수 있다. 사용자가 선택하기 전에는 기존 관찰을 이동·삭제하지 않는다.
- 관련 항목 확인을 마치기 전에는 검토 완료로 표시하지 않는다. 임시 내용은 계속 보존하고, 초안 다운로드는 가능하되 현재 상태를 표시한다.

**완료 기준:** 도움 요청 목표를 차례 지키기로 바꿔도 이전 자동차 놀이 관찰이 새 목표의 관찰로 조용히 섞이지 않는다. 단순 표현 수정은 관찰을 잃지 않는다. 이 과정의 생성 횟수와 API 호출 수는 증가하지 않는다.

### P1-3. 입력 분량과 오류 안내

| 항목 | 생성에 사용할 최대 글자 수 | 필수 여부 |
| --- | ---: | --- |
| 현재 수행 모습 | 500자 | 필수 |
| 흥미와 강점 | 500자 | 선택 |
| 월 목표 | 500자 | 필수 |
| 기존 IEP 목표 | 500자 | 선택 |
| 보호자의 교육적 요청 | 500자 | 선택 |
| 활동 참여·안전에 필요한 지원 | 500자 | 선택 |
| 합계 | 3,000자 | 모든 칸을 채운 경우 |

- 추가 사용자 요청으로 일지와 같은 글자 수 계산 및 브라우저 `maxlength`를 사용한다. 공백·줄바꿈 포함, 입력칸의 `value.length` 기준이며 수동으로 한글 조합을 끊는 코드는 추가하지 않는다.
- 입력칸 우측 상단에 일지와 같은 `현재/최대자` 표시를 항상 보여 준다. 남은 분량·줄여 달라는 별도 문구는 표시하지 않는다.
- 새 입력과 붙여넣기는 일지처럼 브라우저가 최대 길이까지만 허용한다. 기존 저장본의 초과 내용은 열 때 자르지 않으며, 새 생성 시에는 입력 한도를 검사하고 생성권을 쓰지 않는다.
- 기존 저장본은 새 제한을 넘더라도 그대로 열고 내려받을 수 있다. AI 생성 입력 제한과 생성 이후 수동 편집 분량은 별개다. 결과의 수동 편집은 현재 목업의 항목당 2,400자 범위를 유지하되 기존 장문을 마이그레이션하며 자르지 않는다.
- 연령대 누락, 없는 날짜, 종료일 역전, 서로 다른 달, 공백만 입력한 필수 내용은 기존 회색·초록색 UI 안에서 짧게 안내한다. 브라우저 기본 말풍선은 쓰지 않는다.

**완료 기준:** 299/300/301자, 499/500/501자, 줄바꿈, 이모지, 한글 조합, 긴 붙여넣기, 기존 장문에서 표시·검사·보존이 일치한다. 새 입력은 한도를 넘지 않고, 기존 초과 입력의 오류 상태에서는 생성이 0회다.

### P1-4. 결과 화면과 저장 동선

입력 화면의 대상·연령대·기간, 1. 현행수준과 2. 교육목표의 두 칸 배치는 유지한다. 결과 화면에 다시 7개의 탭이나 단계 표시를 추가하지 않는다.

```text
계획 작성 | 저장한 계획
관리대상         연령대         월 계획 기간

[현재 수행 모습]               [흥미와 강점]
[월 목표]                      [기존 IEP 목표]
추가 정보 (선택) 펼침

이번 이용기간 생성 가능 · 다음 갱신일     [AI 계획 만들기]
```

결과에서는 아래 순서로 검토한다.

```text
대상·계획 기간·수정 상태               [계획서 보기] [내려받기]
현행수준·월 목표 요약                  펼쳐서 바로 수정
활동 계획                             기본 펼침
진행 방법·교사 지원                    기본 펼침
평가방법·평가초점                      기본 펼침
교육과정 연결·세부 준비                펼침
실제 관찰·다음 달 검토                 실행 후 작성

수정 상태                             [변경 내용 저장]
```

- 교사의 목표 원문과 첫 문장 일부를 코드로 보여주는 요약이며 요약 AI를 호출하지 않는다. 접혀 있어도 제목과 값의 유무를 확인할 수 있다.
- 준비·진행 순서·반응별 지원의 실제 내용은 유지한다. 페이지를 줄이기 위해 필요한 실행 내용을 삭제하지 않는다. 필요한 정보만 펼쳐 보는 방식으로 읽기 부담을 줄인다.
- 모든 펼쳐진 본문은 바로 편집한다. 별도 `내용 수정` 버튼을 요구하지 않는다. 편집 중인 입력칸은 자동으로 접지 않는다.
- 실제 관찰과 다음 달 검토는 현재 계획 안의 실행 후 기록 영역에 두고, 추가 최상위 탭으로 나누지 않는다. 관찰이 없는 경우 명확히 빈 상태이며 AI가 결과를 만들어 넣지 않는다.
- 저장 영역은 화면 하단에서 접근 가능하게 한다. 본문 아래 충분한 공간을 확보해 마지막 입력칸·모바일 키보드·오류 메시지를 가리지 않는다. 성공 전에는 저장 완료를 표시하지 않는다.
- 출력용 계획서는 기존 7개 항목을 유지한다. 빈 선택 항목은 숨기고 미작성 실제 관찰은 미기록으로 표시한다. 출처 정보·불필요한 설명문을 다시 늘리지 않는다.
- 기존 초록색, 회색 입력칸, 14/16/20px 글자 체계와 공통 본문 폭을 사용한다.

**완료 기준:** 데스크톱과 390px 화면에서 핵심 계획·저장에 접근 가능하고, 키보드로 숨겨진 오류 필드에 이동할 때 해당 영역이 열린다. 펼침·요약·계획서 전환·다운로드는 API 0회다. 화면을 접어도 출력 내용이 사라지지 않는다.

### P2-5. 다음 달 계획 복사

- 저장한 계획에서 `다음 달 계획으로 복사`를 제공한다. 새 문서 ID와 다음 달 기간을 만들며 원본을 수정하지 않는다. 새 기간 기본값은 다음 달 1일~말일이고 달력에서 수정할 수 있다.
- 목표·활동·지원·평가계획은 가져오고 실제 관찰, 이전 목표의 평가 결과, 검토 완료 상태는 가져오지 않는다. 새 계획은 수정 가능한 초안이다.
- AI 생성권은 사용하지 않는다. 복사본을 직접 수정해 저장하는 흐름이 기본이며 AI를 백그라운드에서 호출하지 않는다.
- 대상에게 이미 작성 중인 초안이나 다음 달 계획이 있으면 `기존 계획 열기`를 먼저 제공한다. 별도 수동 사본은 만들 수 있으나 기존 초안을 덮어쓰지 않는다.
- 새 계획을 추가하거나 복사하더라도 이미 쓴 해당 대상의 AI 이용량은 초기화되지 않는다. 문서 수와 AI 생성 횟수를 분리한다.

**완료 기준:** 9월→10월, 12월→1월, 윤년 2월 복사가 올바르다. 지난달 원본·관찰·서식과 다른 대상의 초안이 유지된다. 복사 전후 생성권은 같다.

## 3. 사용자에게 보여줄 상태 문구

선택한 대상의 상태를 생성 버튼 근처 한 줄에만 표시한다. 계정 전체 사용 현황은 요금제/이용량 화면에서 확인한다. 단순 동작에 매번 확인 팝업을 띄우지 않는다.

| 상태 | 표시 | 가능한 행동 |
| --- | --- | --- |
| 생성 가능 | 이번 이용기간 생성 가능 | AI 계획 만들기, 직접 작성, 지난 계획 복사 |
| 입력 오류 | 해당 칸의 짧은 오류 | 입력 수정, 임시 내용 보존 |
| 생성 중 | 계획을 작성하고 있어요 | 다른 기록 열람·수정, 진행 상태 복귀 |
| 완료 | 생성된 계획 표시 | 바로 수정, 검토 후 저장, 내려받기 |
| 이미 사용 | 이번 이용기간 사용 완료 · 다음 이용 10월 26일 | 계획 보기, 직접 작성, 복사 |
| 확정 실패 | 계획을 완성하지 못했어요. 이용 횟수는 그대로예요 | 보존된 입력으로 다시 시도, 직접 작성 |
| 결과 확인 중 | 작성 상태를 확인하고 있어요 | 입력 보존, 기존 작업 조회. 새 요청 즉시 중복 전송 금지 |
| 반복 오류로 일시 중단 | AI 작성이 잠시 지연되고 있어요. 잠시 후 다시 시도해 주세요. | 입력·사용 가능 횟수 보존, 수동 작성 유지 |
| 목표 변경 | 목표가 바뀌어 활동·지원·평가를 다시 확인해 주세요 | 해당 항목 직접 수정·확인 |
| 저장 충돌 | 기존에 구현한 다른 탭 변경 안내 | 현재 내용 백업, 최신 내용 불러오기 |

최종 실패 여부가 확인되지 않은 타임아웃에는 횟수를 돌려줬다고 먼저 표시하지 않는다. AI 생성 결과가 보관됐다는 사실과 교사의 검토 완료는 서로 다른 상태다.

실제 API 예산 검수에서는 일지·리포트의 기존 2~3천원 계산을 새 가정으로 덮어쓰지 않고 실제 사용 내역과 대조한다. IEP는 성공 건·실패 건·복구 호출·입력/출력/생각 사용량을 분리한다. 평균 약 50원/건을 넘어가는 원인이 확인되면 자료량·출력량·내부 중복 호출을 조정하며 사용자에게 제공한 생성권을 원가만으로 몰래 차감하지 않는다.

IEP 호출 범위는 기존 설계대로 교사가 쓴 1~2번을 제외한 3~6번 제안이다. 실제 관찰·저장·표·복사는 모델에 맡기지 않는다. 입력 6,000토큰·출력/생각 합산 4,096토큰은 연결 전 시험 설정이며 모델별 적합성과 완성 품질 확인 없이 원가 상한이 보장됐다고 표시하지 않는다.

## 5. 구현 순서와 전달 범위

1. 대상별 이용권·생성 상태·입력 분량·모의 성공/실패를 구현한다.
2. 직접 수정과 생성의 분리, 목표 변경 시 관찰 보존을 구현한다.
3. 결과 접기/펼치기와 저장 접근성을 정리한다.
4. 다음 달 복사와 원본 보호를 구현한다.
5. 위 QA를 합성 데이터로 수행하고 기존 일지·리포트 저장 흐름을 회귀 확인한다.

목업의 사용량 저장은 UI 시연용이다. 브라우저 저장을 초기화하면 우회할 수 있으므로 실제 이용권·결제·권한·원가 통제의 검수 통과로 간주하지 않는다. 그 부분은 AI 연결 시 서버에서 구현·검증한다. 무료 체험·기관 요금제 등 사용자가 확정하지 않은 상품 규칙은 이번에 추가하지 않는다.
