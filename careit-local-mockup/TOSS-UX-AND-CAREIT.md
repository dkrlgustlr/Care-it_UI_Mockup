# 토스 UX 사례와 케어릿 적용 기준

확인일: 2026-11-08. 토스가 공개한 사례를 살펴보고 케어릿에 적용할 가설을 정리했다. 아래의 케어릿 적용안은 토스에서 효과가 검증된 기능이 아니라, 케어릿 사용자와 테스트할 제안이다. 이번 조사에서는 목업의 기능을 변경하지 않았다.

## 방향

케어릿의 재방문은 접속 횟수 자체보다 **필요할 때 기록을 쉽게 남기고, 이전 기록을 다시 활용할 수 있는 경험**에서 출발한다. 알림·배너로 방문을 강요하기보다 일지 작성, 이어 쓰기, 리포트 확인이 필요한 순간에 쉽게 이어지도록 한다. 실제로 도움이 되는지는 사용자 관찰과 사용 데이터를 함께 확인한다.

## 1. 핵심 가치를 발견하기까지의 단계를 줄인다

**토스 사례:** 고양이 키우기 서비스에서 아이템을 받으려면 홈에서 별도 메뉴로 들어가야 했다. 홈에서 바로 받을 수 있도록 바꾼 뒤, 전체 평균에서는 차이가 작았지만 주 4일 이하 방문한 사용자 그룹의 재방문이 개선됐다고 토스가 설명한다. 이는 해당 게임의 사례이며 케어릿에도 같은 효과가 난다는 뜻은 아니다. [토스: 고양이 사일로의 리텐션 실험](https://toss.tech/article/undercover-silo-5)

**케어릿 적용 가설:** 홈에서 관리대상별 작성 전·임시저장·완료 상태와 해당 행동을 바로 이해하게 한다. 임시저장한 대상은 이어 쓰기로 연결하고, 최근 리포트는 해당 내용을 열 수 있게 한다. 신규 사용자는 첫 기록을 마치고 다시 찾는 과정에서 제품의 가치를 확인할 수 있어야 한다. 새 버튼을 무작정 더하기보다 기존 진입점이 실제 목적지로 연결되는지 먼저 점검한다.

**확인:** 처음 방문한 사람이 원하는 대상의 기록을 시작하고, 나중에 중단한 기록을 다시 찾을 수 있는지 관찰한다. 신규 사용자와 기존 사용자의 결과를 구분해 본다.

## 2. 막히는 순간을 실제 사용 환경에서 없앤다

**토스 사례:** 가입 화면에서 모바일 키보드가 입력 필드와 다음 버튼을 가려 다음 행동을 찾기 어려웠다. 토스는 입력 위치와 흐름을 다시 설계하고 사용성 테스트를 했다. 필드를 여러 페이지로 나누는 방법도 검토했지만 입력마다 다음을 누르는 부담이 있다고 보았다. [토스: 거꾸로 입력하는 가입 화면](https://toss.tech/article/toss-signup-process)

**케어릿 적용 가설:** 모바일에서 키보드가 일지 입력란이나 저장 행동을 가리지 않는지 살펴보고, 500자 제한과 필수 입력 오류는 해당 항목 가까이에서 이해할 수 있게 표시한다. 일지 작성처럼 여러 내용을 비교하며 쓰는 화면은 입력칸 하나마다 페이지를 나누지 않는다. PC에서는 넓은 화면을 활용해 맥락과 입력을 함께 볼 수 있는지도 살핀다.

**확인:** 모바일·PC 각각에서 기록을 쓰고 저장할 때 버튼을 찾지 못하거나, 오류를 이해하지 못하거나, 작성 내용을 잃을 뻔하는 순간을 기록한다. 특히 긴 이름과 작은 화면을 포함한다.

## 3. 상태와 다음 행동을 명확히 알린다

**토스 사례:** 시니어 사용성 조사에서 일부 사용자는 화살표나 텍스트가 클릭 가능한지 알아차리기 어려웠고, 작은 예시 표식을 놓쳐 예시 화면을 실제 정보로 오해했다. 토스는 진입점과 문구, 예시의 명확성을 개선 방향으로 제시했다. 조사 대상의 특성을 모든 사용자에게 일반화하지 않는다. [토스: 시니어 사용자가 어려워하는 UX 5가지](https://toss.tech/article/senior-usability-research)

**케어릿 적용 가설:** ‘작성 전’, ‘임시저장’, ‘완료’는 실제 상태에 맞는 문구로 보여 주고, 클릭할 수 있는 영역은 일관된 형태와 구체적인 동작명으로 표현한다. 일지 예시나 목업의 샘플 데이터는 실제 사용자 기록으로 오해하지 않게 표시한다. 리포트 생성이 불가능하면 ‘일지가 3일 미만’처럼 실제 이유와 필요한 다음 행동을 알려 준다. 가능 여부는 해당 대상과 주간 기록을 기준으로 확인해야 한다.

**확인:** 사용자가 설명 없이 어디를 누를지, 예시인지 실제 기록인지, 현재 저장됐는지 말할 수 있는지 확인한다. 색깔만으로 상태를 구분하지 않는다.

## 4. 기다리는 동안에는 진행 상황을 정직하게 알려 준다

**토스 사례:** 대출 심사 로딩 화면에서 사용자가 화면에 표시된 정보의 진실성을 의심한다는 인터뷰를 바탕으로, 실제 상품 정보를 보여 줘 기다리는 경험을 개선하려는 가설을 세우고 실험했다. 토스는 인터랙션이 신뢰와 지표 개선에 기여한 사례로 소개한다. [토스: 인터랙션, 꼭 넣어야 해요?](https://toss.tech/article/interaction)

**케어릿 적용 가설:** 나중에 실제 리포트 생성이나 AI 기능이 연결되면 진행 중·완료·실패를 구별하고, 대기 중 화면 이동이나 재시도 가능 여부를 실제 동작에 맞춰 안내한다. 없는 진행률이나 가상의 처리 단계를 만들지 않는다. 현재 목업에서 AI가 연결된 것처럼 표현하지 않는다.

**확인:** 대기·실패 상황에서 사용자가 중복 요청을 시도하는지, 작성 내용이 보존됐는지와 다음에 할 일을 이해하는지 확인한다.

## 5. 출시 후에도 사용자를 보고 다시 확인한다

**토스 사례:** 토스는 출시 전 프로토타입뿐 아니라 배포된 제품을 실제 휴대폰에서 쓰는 모습을 관찰할 필요를 강조했다. 또 홈 개편 직후와 약 한 달 뒤 의견을 비교하며 일상적으로 쓰는 서비스는 익숙해진 뒤의 경험도 살펴볼 필요가 있다고 설명했다. [토스: 점심 시간에 사용자를 만난다](https://toss.tech/article/user-interview), [토스: UX 리서치 방법론](https://toss.tech/article/26109)

**케어릿 적용 가설:** 보호자·현장 교사 등 실제 이용 맥락이 다른 사람들에게 일지 작성, 저장 후 이어 쓰기, 주간 리포트 확인을 부탁하고 설명 없이 행동을 관찰한다. 첫 사용뿐 아니라 실제 사용이 쌓인 뒤에도 불편을 다시 묻는다. 테스트는 샘플 데이터를 사용하고 민감한 실제 기록을 요구하지 않는다.

**확인할 지표의 예:** 대상 선택 후 기록을 저장한 비율, 저장까지 걸린 시간, 저장 오류와 작성 중단, 첫 기록 후 일정 기간 내 실제 기록 작업으로 돌아온 비율. 기간·대상·분모는 측정 전에 정하고, 소수 인터뷰 결과와 수치는 함께 해석한다. 숫자를 높이려고 불필요한 알림을 늘리지 않는다.

## 케어릿에 우선 적용해 볼 순서

1. **홈:** 대상별 현재 상태와 이어 쓰기·리포트 확인 경로가 한눈에 이해되는지 점검한다.
2. **일지:** 저장 상태, 입력 제한, 오류와 모바일 키보드 환경을 점검한다.
3. **리포트:** 선택한 주의 생성 가능 여부와 이유가 실제 조건에 맞는지 점검한다.
4. **첫 사용과 재방문:** 첫 기록을 마친 뒤 다음 작업을 찾는지 실제 사용자에게 확인한다.
5. **향후 AI 연결:** 예상 대기와 실패·재시도 안내를 실제 구현에 맞춰 설계한다.

이는 조사에 따른 제안과 검증 순서이며, 재방문율 향상을 보장하는 확정 규칙은 아니다. 구독 조건과 해지 방법은 숨기지 않고, 알림은 사용자가 선택하고 끌 수 있도록 설계한다.
