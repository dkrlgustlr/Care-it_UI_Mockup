# IEP 목업 QA 결과 · 2026-09-26

이 결과는 **AI를 연결하지 않는 UI/UX 목업**을 기준으로 정리했다. 화면 흐름과 예시 결과를 체험하고 수정·저장·출력하는 동작이 검수 대상이다. 실제 AI 생성 품질이나 운영 서버 기능은 구현 요구사항에 포함하지 않는다.

기본 입력·직접 수정·저장·재열기는 정상이다. 발견했던 **여러 탭의 저장 충돌**, **계획서에 입력 안내가 출력되는 문제**, **가져온 데이터의 날짜 검증**을 수정하고 재검수했다.

기존 사용자 저장 데이터 대신, 별도 저장 키를 가진 합성 대상 A/B와 별도 HTML을 사용했다. 수정과 검수는 현재 로컬 목업에 적용했으며 GitHub에는 업로드하지 않았다.

## 수정한 문제의 최초 재현

### 1. P1 · 두 탭에서 편집하면 먼저 쓴 내용이 사라짐 — 브라우저 재현

- 재현: 같은 테스트 페이지를 두 탭에서 연다. 탭 A에서 현재 수행 모습을 변경한다. 새로고침하지 않은 탭 B에서 흥미와 강점만 변경한다. 탭 A를 새로고침한다.
- 결과: 탭 A의 새 관찰이 원래 관찰로 돌아가고 탭 B의 흥미와 강점만 남는다. 충돌 안내도 없다.
- 원인: `mockup.js:66`에서 각 탭이 가진 전체 상태를 localStorage에 덮어쓴다. 다른 탭의 최신 상태와 병합하거나 저장 버전을 비교하지 않는다.
- 권장: 오래된 탭에서 다른 탭의 수정 내용을 덮어쓰지 못하게 막는다. 목업에서는 충돌 안내와 새로고침 유도로 시작할 수 있으며, 서버나 복잡한 병합 기능까지 구현할 필요는 없다.
- 완료 기준: 두 탭에서 서로 다른 항목을 수정해도 한쪽 변경이 조용히 사라지지 않아야 한다.

### 2. P2 · 빈 선택 항목의 입력 안내가 완성 계획서 본문에 출력됨 — 브라우저 재현

- 재현: 연결할 기존 IEP 목표를 비운 계획을 저장한 뒤 계획서 보기를 누른다.
- 결과: 빈칸 대신 “기존 IEP 목표가 있으면 연결해 주세요.”가 계획 및 기록 칸에 출력된다.
- 원인: `iep.js:214`의 `planTable()`이 빈 값을 입력창용 `EMPTY_LABELS` 문구로 바꾼다. 내려받기도 같은 표 함수를 사용한다.
- 권장: 작성 화면의 안내와 출력값을 분리한다. 없는 선택 항목은 행을 숨기거나 `—`로, 아직 작성하지 않은 실제 평가 결과는 `미기록` 등 상태로 표시한다.
- 완료 기준: 미리보기와 내려받은 문서에 입력을 요청하는 안내 문구가 계획 내용처럼 남지 않는다.

### 3. 낮은 우선순위 · 가져온 데이터의 존재하지 않는 날짜가 통과함 — 함수 검증

- `2026-02-01 ~ 2026-02-30`에 오류가 반환되지 않았다.
- 정상 윤년 날짜, 정상 2월 말은 통과했고, 시작/종료 역전과 서로 다른 달은 거절했다.
- 원인: `iep.js:229`의 `periodError()`는 값 존재·문자열 순서·같은 달 여부만 검사한다.
- 범위: 달력 UI에서는 2월 30일을 선택할 수 없다. 비정상 저장 데이터를 읽는 경우의 보완 사항이며 일반 시연을 막는 문제는 아니다.
- 권장: 저장 데이터를 읽을 때 실제 달력 날짜인지 검사한다.

## 목업의 범위로 인정할 부분

- **연령별 같은 예시:** 같은 관찰·목표로 연령만 바꾸면 5개 구간의 결과 본문이 동일하다. 현재 `iep.js:140`은 요청/또래/일상/일반 키워드에 따른 예시 생성이며 실제 AI 판단을 구현하지 않는다. 현재의 `제안 예시` 표시를 유지하면 되고, 연령별 생성 로직을 새로 만드는 것은 이번 필수 수정 대상이 아니다.
- **자유 입력 문장의 개인정보:** 별도 이름·기존 메모·생년월일·일지 원문은 계획 입력에서 제외된다. 문장 안의 가상 이름·연락처는 그대로 남는 것을 확인했으나, 외부 AI 전송 자체가 없으므로 전송 전 자동 제거 기능은 이번 목업 범위에서 제외한다. 이 판단이 로컬 저장 데이터의 익명화를 보장한다는 뜻은 아니다.
- **AI·운영 서버 기능:** 실제 모델 호출, 자료 검색, 생성 품질, 모델 응답 오류, 계정·기관별 서버 권한은 이 목업의 검수 대상이 아니다. 미구현 결함이나 출시 전 필수 작업으로 집계하지 않는다.

## 정상 동작을 확인한 부분

- 저장한 계획의 교사 지원과 실제 관찰을 직접 수정한 후, 월 목표 입력을 다시 반영해도 해당 수정값이 유지됐다.
- 변경 내용 저장 → 새로고침 → 저장한 계획 재열기에서도 값이 보존됐고 저장한 계획 수가 중복 증가하지 않았다.
- 수정 시 상태가 수정 중으로, 명시적 저장 뒤 검토 완료로 변경됐다.
- 합성 대상 A/B의 작성 초안, 저장 목록, 기간은 분리됐다. B의 기간을 9월 5~20일로 바꿔도 A는 9월 1~30일을 유지했다.
- 표 미리보기에 직접 수정한 지원·실제 관찰과 `<검수 & 보존>` 문자열이 정상 표시됐다. 이것만으로 모든 보안 입력 검증을 완료했다고 판단하지는 않는다.
- 필수 내용에 공백만 입력하면 생성이 중단되고 두 항목에 각각 안내가 나타났다. 초점은 첫 오류인 현재 수행 모습으로 이동했다.
- 오류 요소에 `aria-invalid`와 안내 연결 `aria-describedby`, 안내에는 `role=alert`가 있었다. 정상 내용을 넣으면 각 오류가 해제됐다.
- 390px 화면에서 페이지 가로 넘침이 없었다. 320px 화면의 달력은 좌측 8px, 우측 312px 안에 표시됐다.
- 달력에서 시작일 → 종료일 순서로 선택하면 값이 갱신되고 기간 버튼으로 초점이 돌아왔다.
- 생성 시 실제 관찰·평가 결과는 빈 값으로 시작했다.
- 기존 주간 데이터의 보관·월간 이전, 직접 수정한 내용·ID·상태·계획 수 보존 검사는 통과했다.

## 목업에서 추가 확인하면 좋은 부분

- 개별 계획서와 전체 백업의 실제 HTML 다운로드 파일은 재검수에서 확인했다. PDF 인쇄 페이지 나눔은 확인하지 않았다.
- 내려받은 백업을 localhost에서 여는 검수는 통과했다. file:// 직접 열기는 브라우저 도구의 URL 보안 정책이 차단하므로 이번 자동 검수에서 확인하지 못했다.
- 화면 읽기 프로그램의 실제 음성 안내, 모든 브라우저/실기기, 장문 출력은 별도 검수가 필요하다. 저장 용량 초과·저장 실패의 처리는 모의 저장소로 확인했으며 실제 브라우저 용량을 채우는 검수는 하지 않았다.
- 위 항목은 미확인 범위이며 발견된 버그로 집계하지 않는다. 모든 운영 환경에 대한 검증을 목업 완료 조건으로 요구하지 않는다.
