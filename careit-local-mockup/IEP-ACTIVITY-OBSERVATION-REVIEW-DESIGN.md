# IEP 활동 제안·관찰 연결·결과 검토 설계안

2026-09-26. 사용자 요청에 따른 설계안이며 아직 화면과 동작에 적용하지 않았다. 실제 AI/API는 연결하지 않는다.

## 범위와 현재 상태

- 작성 화면의 현행수준·월 목표 중심 입력, 여섯 입력칸 각각 500자, 대상별 결제 이용기간당 1회 생성 정책을 유지한다.
- 현재 `iep.js`에는 활동, 준비물, 진행 순서, 반응별 지원, 평가초점이 이미 있다. 활동과 준비가 분리되어 있어 실행 순서에 맞게 재배치한다.
- 현재 실제 관찰은 빈칸으로 시작하고, 목표 변경 이력과 다음 달 복사가 구현되어 있다. 여기에 목표와 일지의 연결을 추가한다.
- 입력 자동 요약, 지난 일지로 현행수준 자동 작성, 추가 AI 평가·재생성, 주 계획, 협의회 관리 기능은 이번 범위에 포함하지 않는다.
- 현재 월 목표 입력 한 칸을 하나의 목표 단위로 연결한다. 입력 문장을 임의로 여러 목표로 분리하지 않는다. 복수 목표 관리 UI는 별도 범위다.

## 1. 활동 제안을 실행 순서로 모으기

결과 화면을 다음 순서로 정리한다.

1. 월 목표 요약과 교사 입력 보기
2. 활동 제안
3. 관찰할 내용
4. 관찰·월말 평가
5. 교육과정 연결 — 접힘

활동 제안은 월 목표에 연결된 활동 2개를 기본으로 한다. 교육적으로 정해진 수가 아니라 읽는 부담을 줄이기 위한 UI 기본값이다. 수동 추가·삭제가 가능하며 주차별 배정은 하지 않는다.

| 활동 안의 항목 | 표현 방식 |
| --- | --- |
| 활동명·목표와의 연결 | 무엇을 하며 어떤 행동을 연습하는지 짧게 표시 |
| 준비물·환경 | 준비물 목록과 배치·참여 조건을 한 영역에 배치 |
| 진행 순서 | 시작 → 목표를 시도할 상황 → 교사 지원 → 마무리, 3~4단계 |
| 반응에 따른 도움 | 스스로 반응할 때 / 도움 뒤 반응할 때 / 반응하거나 참여하기 어려울 때 |

첫 활동은 기본 펼침, 두 번째 활동은 활동명이 보이는 접힌 상태로 제공한다. 모든 펼쳐진 입력칸은 즉시 수정할 수 있다. 기존 필드를 억지로 두 활동으로 자동 분해하지 않으며, 기존 계획은 내용을 보존한 활동 1개로 보여 준다.

자동차 놀이 예시: 교사가 입력한 월 목표가 도움 요청이면 자동차 길 잇기를 제안하고, 자동차·길 블록·이미 사용하는 요청 그림을 준비한다. 실제 도움이 필요한 상황에서 표현할 여유를 주고, 스스로 요청하면 필요한 도움을 제공한다. 표현이 어렵다면 익숙한 도구·짧은 시범으로 지원한다. 목표를 연습시키기 위해 필요한 도움을 의도적으로 거부하는 활동을 만들지 않는다.

관찰할 내용은 별도 한 카드에 목표와 직접 연결되는 1~3개 항목으로 제안한다. 예: 표현 방식, 추가 도움의 종류, 요청 뒤 놀이 참여. 이 항목은 관찰 안내이며 실제 관찰값이나 달성 판정이 아니다. 교사가 정하지 않은 성공 횟수·달성률·시간 기준은 생성하지 않는다.

## 2. 일지 연결 → 월말 평가 → 다음 달 검토

관찰·평가 카드는 저장한 계획 상세에서도 동일하게 사용한다. 별도 최상위 탭이나 매일 작성해야 하는 새 양식은 추가하지 않는다.

```text
관찰·월말 평가                         [일지 연결]

9월 8일   일지 내용 일부               [보기] [연결 해제]
9월 15일  일지 내용 일부               [보기] [연결 해제]

관찰 메모 (선택)                       [메모 추가]

월말 평가                             0/500자
[실제 기록을 보면서 교사가 작성]

다음 달 검토
[유지] [조정] [추가 관찰]
[검토 메모 — 선택, 500자]

[다음 달 계획으로 복사]
```

- `일지 연결`을 누르면 같은 관리대상·계획 기간 안의 저장된 일지만 날짜순으로 표시한다. 날짜, 짧은 본문 미리보기, 선택 체크박스, `선택한 일지 연결` 버튼으로 구성한다.
- 교사가 관련성을 판단해 연결한다. AI로 일지를 읽거나 관련 일지를 자동 선정하지 않는다. 같은 목표에 같은 일지를 중복 연결하지 않는다.
- 일지 수는 자료 수일 뿐, 시도 횟수·성공 횟수·달성률로 해석하지 않는다. 일지를 연결하면 별도 관찰 메모는 필수가 아니다.
- 일지가 없는 날에는 날짜와 500자 관찰 메모를 직접 추가할 수 있다. 실제 행동과 도움 정도를 적는 예시를 placeholder로 제공한다. 관찰을 작성하지 않았다고 미달성 처리하지 않는다.
- 일지 열람은 모달/상세 패널로 제공해 IEP 입력 내용을 유지한다. 일지 수정이 필요하면 현재 IEP 초안을 보존한 뒤 일지로 이동하고 돌아올 수 있게 한다.
- 연결 해제는 일지를 삭제하지 않는다. 원본 일지가 휴지통에 있거나 삭제되면 본문을 숨기고 원본을 볼 수 없다는 상태를 표시한다. 원본 변경 시 연결 목록에서 수정 상태를 알리되 작성한 월말 평가를 자동 변경하지 않는다.
- 월말 평가는 시작부터 빈칸이다. 교사가 관련 기록을 보면서 직접 작성하고, 다음 달 검토도 교사가 선택한다. 기록이 없어도 계획 자체를 저장할 수 있다.
- 현재 `adjust`에 생성되는 긴 조건부 다음 달 안내는 새 계획에서 평가 결과처럼 미리 채우지 않는다. 조건에 따른 도움은 활동 카드에 두고, 다음 달 결정·메모는 실행 후 작성한다. 기존 저장본의 `adjust` 내용은 삭제하지 않고 보존한다.
- 다음 달 복사 시 목표·활동·지원·관찰 항목을 이어받고, 실제 관찰·일지 연결·평가·다음 달 결정은 비운다. 이전 평가는 이전 계획 링크로 참고할 수 있다. 새 목표나 현행수준을 자동 확정하지 않는다.
- 월 목표의 의미가 바뀌면 기존 목표 버전에 연결된 일지·관찰·평가를 함께 보관한다. 단순 표현 수정은 기존 연결을 유지한다. 기존 목표 변경 확인 흐름을 확장한다.

## 3. 작성 주체와 확인할 부분을 간단히 구분

| 구역 | 화면 표현 | 내용의 성격 |
| --- | --- | --- |
| 현행수준·교육목표 | 교사 입력 | 교사 원문 유지 |
| 활동·관찰 항목 | 제안 예시 — 목업 / AI 제안 — 실제 연동 후 | 실행 방안이며 실제 수행 사실이 아님 |
| 실제 관찰·월말 평가 | 교사 기록 | 초기 공란, 교사가 실제 기록 작성 |

- 구분은 영역 제목 옆의 작은 표시로 한 번씩만 한다. 입력칸마다 배지·설명문·출처를 반복하지 않는다. 회색 입력칸·초록색 강조·공통 본문 폭·14/16/20px 체계를 사용한다.
- 제안 문장은 바로 수정한다. 교사가 수정한 부분은 내부에 수정 여부를 보관하지만 모두를 새 배지로 표시하지 않는다. 상단의 기존 수정 상태를 재사용한다.
- `확인 필요`는 실제 입력이 바뀌어 기존 제안과의 연결을 다시 살펴야 할 때 관련 활동·관찰 항목에만 표시한다. 매번 저장을 위해 모든 칸을 확인하도록 요구하지 않는다.
- 월 목표·현행수준·참여 지원 등 변경 감지는 일반 코드로 처리한다. 의미가 맞는지 자동 검증했다고 표시하지 않는다.
- 출처 공개, 공식 검증 표시, 달성률 자동 계산을 추가하지 않는다. 계획 검토 완료와 목표 달성을 별도 상태로 취급한다.

## 구현 시 최소 변경 범위

- `iep.js`: 활동 묶음 렌더링, 관찰 항목, 일지 연결 선택창, 관찰·평가 기록, 작성 주체 구분, 기존 목표 이력·다음 달 복사 확장.
- `iep.css`: 기존 카드·입력·버튼 토큰을 재사용하고 활동 접힘과 연결 목록 배치만 추가.
- `mockup.js`: 저장 일지를 참조할 안정적인 ID와 수정 정보 제공. 현재 `savedJournals`는 주로 대상+날짜로 저장하므로 기존 자료에 ID를 부여하고 같은 일지 수정 시 유지한다. 시연용 원본 목록도 해당 본문이 실제 있는 항목만 연결 후보로 제공한다.
- 연결은 `planId + goalVersionId + journalId` 기준으로 저장한다. 실제 관찰 메모와 교사 평가를 제안 본문과 분리한다. 일지 전문을 IEP 데이터에 중복 복사하지 않는다.
- 기존 필드명과 7개 항목 출력은 유지 가능한 부분을 재사용한다. 활동 여러 개는 교육내용·교육방법 아래 활동명으로 구분하여 출력하고, 실제 기록이 없는 평가결과는 `미기록`으로 출력한다.
- 새 관찰 메모·월말 평가·다음 달 메모는 각 500자, 일지와 같은 우측 `현재/500자` 표시를 적용한다. 기존 저장된 장문은 보존하며 새 제한 때문에 자르지 않는다. 기존 결과 편집칸의 제한은 이번 안에서 일괄 변경하지 않는다.
- 목업은 자체 예시와 브라우저 저장만 사용한다. 향후에도 최초 계획 생성 1회 안에서 활동·관찰 항목을 함께 반환하고, 연결·편집·월말 평가·복사에는 모델을 호출하지 않는다. 원문 일지와 연결 목록은 AI 입력에 자동 포함하지 않는다.

## 확인 기준

1. 활동 안에서 준비물·진행·반응별 지원을 확인하고 별도 편집 모드 없이 수정할 수 있다.
2. 다른 대상·다른 기간·삭제된 일지는 연결 후보에 노출되지 않으며 같은 일지는 중복 연결되지 않는다.
3. 연결·해제·수정·평가·다음 달 복사 전후 생성 이용량이 변하지 않는다.
4. 일지를 연결하거나 계획을 저장해도 실제 평가와 달성 결과가 자동으로 생기지 않는다.
5. 목표 변경 후 이전 목표의 일지·관찰·평가는 이력으로 남으며 새 목표와 섞이지 않는다.
6. 다음 달 복사는 실제 관찰과 연결을 초기화하고 원본을 유지한다. 기존 다음 달 계획이나 초안을 덮어쓰지 않는다.
7. 기존 저장 계획·장문·직접 수정·계획서 출력이 유지되며 새 활동 구조로 옮길 때 사용자 문장을 잃지 않는다.
8. 390px 화면에서 카드·선택창·저장 버튼이 겹치지 않고 키보드로 접힌 내용과 연결 작업에 접근할 수 있다.
