# 케어릿 목업 그림자 검수 및 통일

## 현재 적용 상태: 카드·팝업 그림자 통일, 회색 컨트롤 그림자 제거

검수 후 사용자 요청에 따라 2026-09-23에 아래 기준을 적용했습니다.

```css
:root { --shadow-ui: 0 4px 12px rgba(22,32,42,0.05); }
```

- 큰 섹션 카드·팝업·주요 초록 버튼·목업 편집 도구의 바깥 그림자는 이 값을 사용합니다.
- 흰색 섹션의 경계를 은은하게 구분하도록 청회색 `#16202A` 불투명도 5%, 아래 거리 4px, 흐림 12px로 조정했습니다.
- 후속 요청에 따라 회색 입력칸·메모칸·드롭다운·날짜 선택칸·보조 버튼·퀵체크·기록 및 요금제 탭의 그림자를 제거했습니다. 선택·hover·focus 상태에서도 회색 컨트롤의 그림자가 다시 생기지 않으며, 선택 배경색과 키보드 포커스 테두리는 유지합니다.
- 퀵체크 선택 항목 사이 간격은 8px입니다. 좁은 간격으로 그림자가 겹쳐 경계가 흐려지는 현상을 줄였습니다.
- 기존 그림자 토큰은 기본적으로 `--shadow-ui`를 참조하며, 회색 컨트롤 범위에서는 `--shadow-hairline`과 `--shadow-chip`을 `none`으로 지정합니다.
- 그림자를 유지하는 영역은 hover, focus 상태에서도 색·진하기·거리·흐림·확장 값이 동일합니다.
- 관리대상 외부 카드의 1px 테두리를 제거했고 모달 배경막은 `rgb(22 32 42 / 35%)`로 통일했습니다.
- 제목 편집 상태는 메모칸과 같은 회색 배경으로 표시하며 밑줄과 그림자는 없습니다. 사이드바 구분선은 유지합니다. 투명 아이콘·기본 체크 컨트롤·비활성 버튼·문서 내부 영역·인쇄용 출력에는 불필요한 그림자를 추가하지 않습니다.
- 최초 통일 시 브라우저에서 10개 화면, 퀵체크·대상 상세·채점·확인 팝업, 홈 카드 focus 상태를 확인했습니다. 이후 위 회색 컨트롤의 그림자 제거를 추가 적용했습니다.

이후 그림자를 변경하려면 `mockup.css`의 `--shadow-ui` 한 곳을 수정하면 됩니다.

---

아래는 **통일 적용 전 검수 기록**입니다. 값 차이와 제안은 변경 전 상태를 설명합니다.

검수일: 2026-09-23. 대상: 현재 로컬 `careit-mockup.html`과 `assets/original.css`, `mockup.css`.
첫 검수 때는 스타일을 변경하지 않고 아래 차이를 기록했습니다.

## 결론

첨부한 일지 화면의 **대상·날짜 선택 영역, 오늘의 메모, 퀵체크, 저장 전 확인**은 모두 같은 그림자입니다.

```css
--shadow-card: 0 8px 22px #00000012;
```

가로 이동 0px, 아래 이동 8px, 흐림 22px, 확장 0px, 검정 불투명도 약 7%입니다. 네 영역의 배경도 모두 흰색이고 테두리는 0px입니다. 카드 크기와 주변 간격, 다른 그림자가 겹치는 위치에 따라 같은 값도 다르게 보일 수 있습니다.

전체 UI에서 실제 값이 다른 곳은 **카드의 hover/focus 상태, 회색 입력 요소, 일부 팝업**입니다.

## 확인 범위와 방법

- 홈, 일지 작성, 리포트, 저장 리포트 상세, 기록, 관리대상, 요금제, 설정, 알림, 일지 편집: 총 10개 화면 상태.
- 데스크톱 너비 1440px와 모바일 너비 390px에서 브라우저의 최종 `getComputedStyle()` 값 비교.
- 대상 선택창, 달력, 퀵체크 생성창, 관리대상 상세창, 채점 문항 편집창, 확인창의 실제 그림자 비교.
- CSS의 모든 그림자 선언과 미디어 조건, hover/focus 선택자 검사. 홈 카드의 focus-within 변화는 브라우저에서도 확인.
- 다크 모드의 공통 그림자 변수와 홈 카드 실제 값 확인. 다크 모드 전체 화면을 별도로 모두 검수한 것은 아닙니다.
- 사용자가 추가한 디자인 CSS는 현재 비어 있어 별도 덮어쓰기 영향은 없습니다.
- 실제 서비스 서버에는 변경을 저장하지 않았습니다. 브라우저 화면 크기·테마는 검수 후 복원했습니다.

## 기본 흰색 카드

아래 항목은 PC·모바일 모두 `0 8px 22px #00000012`로 같습니다.

| 화면 | 같은 그림자를 쓰는 영역 | 추가 차이 |
|---|---|---|
| 홈 | 주간 기록 추이, 관리대상 카드 | 관리대상 카드는 hover/focus에서 달라짐 |
| 일지 작성 | 상단 선택 영역, 오늘의 메모, 퀵체크, 저장 전 확인 | 첨부 영역 4개 모두 같음 |
| 리포트 | 작성 대상, 생성 조건, 저장 리포트 외부 카드 | 내부 A4 문서는 그림자 없이 1px 선 사용 |
| 기록 | 기간 필터, 기록 목록 외부 영역 | 탭은 작은 컨트롤 그림자 사용 |
| 관리대상 | 활성·비활성 대상 카드 | 모두 1px 검정 약 8% 테두리가 추가됨; 비활성 배경은 다름 |
| 요금제 | 무료·스타터·프로 카드 | 현재 요금제는 연한 초록 배경 |
| 설정 | 계정·기기·AI 동의·알림·비활성 대상·탈퇴 | 동일 |
| 알림 | 알림 목록의 카드 | hover에서 달라짐 |
| 일지 편집 | 대상 선택, 영역 이름 설정, 퀵체크 카드 | 퀵체크 카드는 hover에서 달라짐 |

## 차이 1: 카드의 마우스·키보드 반응

다음 다섯 종류는 기본 그림자에서 작은 그림자로 바뀝니다.

```css
/* 기본 */
box-shadow: 0 8px 22px #00000012;
/* hover, 홈 카드의 focus-within */
box-shadow: 0 1px 3px #0000000f;
```

| 위치 | 선택자 | 추가 반응 |
|---|---|---|
| 홈 관리대상 카드 | `.home-recipient-card:hover`, `:focus-within` | 위로 2px 이동, 배경도 변경 |
| 관리대상 카드 | `.recipient-card:hover` | 위로 2px 이동; hover 가능한 정밀 포인터 조건 |
| 알림 카드 | `.notification-list li:hover` | 위로 1px 이동 |
| 퀵체크 설정 카드 | `.configuration-card:hover` | 위로 1px 이동 |
| 요금제 카드 | `.pricing-card:hover` | 위로 2px 이동; 현재 요금제 외 배경 변경 |

불투명도는 약 7% → 6%로 조금 달라지지만, 흐림이 **22px → 3px**, 아래 이동이 **8px → 1px**로 크게 줄어듭니다. 같은 카드라도 마우스 위치나 키보드 초점에 따라 그림자가 확 달라지는 주요 원인입니다. 일지의 큰 섹션에는 이 변화가 없습니다.

## 차이 2: 회색 입력 요소

일지 화면에서 배경은 모두 `#eef3f5`지만 그림자는 다릅니다.

| 요소 | 실제 그림자 | 불투명도 |
|---|---|---|
| 대상·날짜·저장 일지 선택칸 | 없음 | — |
| 자유 메모·서술형 입력칸 5개 | `0 1px 3px #0000000f` | 검정 약 6% |
| 선택 전 퀵체크 칩 | `0 3px 8px #0000000e` | 검정 약 5.5% |
| 선택된 퀵체크 칩 | `0 1px 3px #0000000f` | 검정 약 6% |
| 일반 버튼 | `0 1px 3px #0000000f` | 검정 약 6% |
| 주요 초록 버튼 | `0 8px 18px #0000001a` | 검정 약 10% |

흰색 카드와 회색 입력칸을 구분하는 것은 역할 차이로 볼 수 있습니다. 다만 같은 회색 입력 요소 안에서도 그림자가 없는 것·작은 것·넓은 것이 함께 사용됩니다. 선택된 칩은 배경도 초록색으로 바뀝니다.

앞서 요청한 초록 포커스 테두리는 `outline`이며 그림자와 별개입니다. 흰 틈 제거(`outline-offset: 0`)는 유지되어 있습니다. 편집 가능한 메모 제목의 밑줄 역시 그림자 효과가 아닌 편집 표시 용도입니다.

## 차이 3: 팝업

| 팝업 | 실제 그림자 |
|---|---|
| 드롭다운·달력 | `0 8px 22px #00000012` |
| 퀵체크 생성·편집 | `0 8px 22px #00000012` |
| 관리대상 상세·채점 문항·확인창 | `0 20px 44px #00000024` |

작은 선택창과 큰 모달의 구분은 가능합니다. 하지만 **퀵체크 편집 모달만 일반 카드용 그림자**를 쓰므로 다른 편집 모달보다 퍼짐과 진하기가 작습니다.

배경을 어둡게 덮는 막도 다릅니다. 상세·채점·퀵체크 모달은 `var(--text)`의 35%, 확인창은 고정색 `#16202a`의 40%입니다. 이것은 카드 자체의 그림자와 별개의 차이입니다.

`mockup.css` 상단의 예전 선택창 규칙에는 `--shadow-soft`도 남아 있지만, 현재 popover 규칙이 덮어써 실제 선택창·달력은 위 표의 카드 그림자로 렌더링됩니다. 선언만 보고 더 진한 그림자가 적용됐다고 판단하면 안 됩니다.

## 그 외 구분

- 관리대상 카드의 1px 테두리는 그림자가 같아도 윤곽이 더 진해 보이게 합니다. 앞서 없앤 테두리는 일지의 ‘저장 전 확인’ 영역에만 해당합니다.
- 채점 영역 안의 작은 카드, 보고서 문서와 내부 영역은 테두리 또는 배경으로 구분하며 그림자가 없는 항목도 있습니다. 외부 섹션 카드와 같은 역할은 아닙니다.
- 인쇄용 CSS는 리포트 그림자를 제거합니다. 일반 화면과 인쇄를 구분한 규칙입니다.
- 다크 모드는 카드 그림자 값을 따로 변경하지 않습니다. 배경이 어두워져 같은 검정 그림자라도 더 약하게 보일 수 있습니다.
- 오른쪽 아래 목업 편집 버튼·편집 패널·토스트는 제작 도구이며 별도 고정 그림자를 사용합니다.

## 통일 작업의 우선순위 제안

1. 큰 섹션 카드의 그림자를 기본·hover·focus에서 동일하게 유지할지 결정. 현재 가장 큰 시각적 변화입니다.
2. 회색 입력 요소의 그림자를 한 기준으로 정리. 선택 여부와 초점은 배경색·초록 테두리로 구분할 수 있습니다.
3. 퀵체크 모달의 그림자를 다른 편집 모달과 맞추고, 모달 뒤의 어두운 배경도 공통값 사용.
4. 관리대상 카드의 별도 테두리를 유지할지 확인.

크기가 다른 카드·입력칸·모달을 전부 같은 그림자로 만드는 것보다 **같은 역할과 같은 상태에 같은 값**을 사용하는 기준이 적합합니다.
